# LST Parsing

## Purpose

Разбор deployment-файла `ModuleTableInMemory.lst` (extension «таблицы в памяти» Diasoft 5NT): извлечение деклараций `<Таблица>;<Модуль>` по секциям продуктов и сохранение признака «объявлена как таблица в памяти» в индексе. Покрывает как API-таблицы (`pAPI_*`), так и обычные `p*`-таблицы.

## Requirements

### Requirement: Разбор ModuleTableInMemory.lst

Система SHALL индексировать файлы с расширением `.lst`: файл с каноническим именем `ModuleTableInMemory.lst` разбирается — заголовок секции `[<Продукт>]` открывает группу строк `<ИмяТаблицы>;<ИмяМодуля>`, каждая строка порождает запись признака (продукт из секции, модуль, имя таблицы, привязка к файлу и номеру строки). Прочие `.lst`-файлы (например, `ld_AfterApiReg.lst`) SHALL индексироваться как файлы без сущностей — по прецеденту XML вне `/DSArchitectData/`. Записи признака SHALL жить в привязке к своему файлу: повторная индексация изменённого `ModuleTableInMemory.lst` заменяет все записи файла, исчезновение файла из дерева удаляет его записи (каскад).

#### Scenario: Канонический файл порождает записи признака

- **GIVEN** дерево содержит `DBMaintenance_Ext/Server/ModuleTableInMemory.lst` с секцией `[FA-Administrator]` и строкой `pAPI_AttrValue;API_Administrator`
- **WHEN** выполняется индексация
- **THEN** создана запись признака: таблица `pAPI_AttrValue`, модуль `API_Administrator`, привязка к файлу и номеру строки
- **AND** сам файл отражён в индексе файлов

#### Scenario: Посторонний .lst не порождает сущностей

- **GIVEN** дерево содержит `API_Factoring/Server/ld_AfterApiReg.lst` (формат списков загрузки, не таблицы в памяти)
- **WHEN** выполняется индексация
- **THEN** файл отражён в индексе файлов
- **AND** записей признака «таблица в памяти» из него не создано

#### Scenario: Повторная индексация заменяет записи файла

- **GIVEN** проиндексированный `ModuleTableInMemory.lst`, из которого затем удалена строка `pAPI_Property_Value;API_Administrator` (гипотетическая правка актуального файла)
- **WHEN** выполняется инкрементальный `update`
- **THEN** записи признака этого файла пересозданы по новому содержимому: `pAPI_Property_Value` больше не отмечена, остальные строки сохранены

### Requirement: Нормализация продукта и устойчивость разбора

Продукт из заголовка секции `[<Продукт>]` SHALL нормализоваться механическим правилом нормализации имён продуктов (`FA-Administrator` → `fa-administrator`, `FA-GAAP` → `fa-gaap`) и храниться как справочное поле декларации; нормализация не гарантирует совпадения с каталогом продуктов индекса (например, `FA-Payment` → `fa-payment` при продукте индекса `fa-payments`) — сопоставление признака с таблицами выполняется по имени таблицы, `product_name` в сопоставлении не участвует. Разбор SHALL быть устойчивым: пустые строки и строки-заголовки без табличных строк не порождают записей; корректной считается строка `Таблица;Модуль` с непустым именем таблицы (разделение по первой `;`, поля обрезаются от пробелов); строка вне формата — в том числе табличная строка до первого заголовка секции (у неё нет продукта) — учитывается в ошибках файла, но не прерывает разбор остальных строк.

#### Scenario: Нормализация имени продукта

- **GIVEN** `ModuleTableInMemory.lst` содержит секцию `[FA-GAAP]` со строкой `pRuleDoc_QtyStack;GAAP`
- **WHEN** выполняется разбор
- **THEN** запись признака хранит нормализованный продукт `fa-gaap` как справочное поле декларации
- **AND** сопоставление записи с таблицами индекса идёт по имени таблицы, без участия `product_name`

#### Scenario: Пустая секция не порождает записей

- **GIVEN** `ModuleTableInMemory.lst` содержит `[FA-Contracts]`, за которой сразу следует следующая секция
- **WHEN** выполняется разбор
- **THEN** записей для продукта `fa-contracts` не создано: пустая секция — управляющая команда установщику (перенести все таблицы в файловую группу), а не декларация таблиц

#### Scenario: Мусорная строка не прерывает разбор

- **GIVEN** `ModuleTableInMemory.lst` содержит корректные строки и строку без `;`
- **WHEN** выполняется разбор
- **THEN** корректные строки порождают записи признака
- **AND** мусорная строка учтена в ошибках файла, прогон индексации не прерван

#### Scenario: Строка до первой секции не порождает записи

- **GIVEN** `ModuleTableInMemory.lst` начинается со строки `pSomeTable;SomeModule`, а первый заголовок `[FA-Administrator]` идёт после неё
- **WHEN** выполняется разбор
- **THEN** запись для `pSomeTable` не создана (нет продукта секции), строка учтена в ошибках файла
- **AND** строки после заголовка разбораны как обычно

### Requirement: Семантика признака «объявлена как таблица в памяти»

Признак SHALL означать «таблица объявлена в памяти декларацией extension» — то есть перечислена в актуальном `ModuleTableInMemory.lst`. Признак декларативен: его отсутствие SHALL NOT трактоваться как утверждение «таблица в файловой группе», поскольку runtime-истина хранится в таблице `tTableInmemory` целевой БД, недоступной индексатору (таблицы, добавленные в память вручную или оставшиеся после сбоя установки, в `.lst` не попадают).

#### Scenario: Обычная p-таблица и API-таблица отмечены одинаково

- **GIVEN** `ModuleTableInMemory.lst` содержит и API-таблицу `pAPI_AttrValue`, и обычную `pRuleDoc_QtyStack`
- **WHEN** выполняется индексация
- **THEN** обе записи признака созданы единообразно — формат не различает API- и обычные таблицы

#### Scenario: Таблица в памяти вручную не отмечена

- **GIVEN** таблица переведена в память вручную DBA и потому отсутствует в `ModuleTableInMemory.lst`
- **WHEN** выполняется `query table` по этой таблице
- **THEN** признак «объявлена как таблица в памяти» не установлен

## Notes

- Источник — deployment-extension «таблицы в памяти»: checkout `fa-dbmaintenance-ext-tbl-in-memory` репозитория `fa-dbmaintenance-ext` (ветка `prj/TblInMemory`); документация — `Modifications/Extension по таблицам в памяти.md`
- Признак декларативен: runtime-истина — `tTableInmemory` целевой БД, недоступна индексатору
- `product_name` — справочное поле (механическая нормализация branchkey); сопоставление с таблицами — только по имени (`query/entity-queries`, `query/api-relations-queries`)
- Прочие `.lst` (ld_AfterApiReg.lst и т.п.) — другой формат (списки путей без `;`), поэтому диспетчеризация по каноническому имени файла, а не по расширению
