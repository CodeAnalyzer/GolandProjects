# Поиск по описаниям процедур и API-контрактов

## Purpose

Полнотекстовый поиск по человеческим описаниям SQL-процедур (header-комментарии) и
API-контрактов (ShortDescription/FullDescription) — точка входа для доменных
вопросов на естественном языке, дополняющая поиск по спекам и поиск по имени.

## Requirements

### Requirement: Поиск по тексту описаний

Система SHALL предоставлять поиск `desc-search`, который по текстовому запросу
находит SQL-процедуры (по имени и header-описанию) и API-контракты (по имени,
краткому и полному описанию), ранжированные по релевантности. Каждая запись
выдачи SHALL содержать: тип сущности (kind), имя, путь к файлу, строку начала,
ранг и сниппет описания.

#### Scenario: Прямой hit по описанию контракта

- **GIVEN** проиндексированный проект с контрактом `API_CCred_BindClassifier`,
  чьё описание содержит «привязка кредитных договоров к классификатору»
- **WHEN** выполняется `desc-search --text "привязка кредитных договоров к классификатору"`
- **THEN** `API_CCred_BindClassifier` возвращён в выдаче
- **AND** запись имеет kind `service`, путь к XML-файлу контракта и сниппет описания

#### Scenario: Hit по описанию процедуры

- **GIVEN** проиндексированный проект с процедурой `ReturnCashFund_Insert`,
  чей header-комментарий описывает возврат сумм из банка-партнёра
- **WHEN** выполняется `desc-search --text "возврат сумм из банка-партнёра"`
- **THEN** `ReturnCashFund_Insert` возвращён в выдаче с kind `procedure`
- **AND** запись содержит путь к SQL-файлу и строку начала процедуры

#### Scenario: Запрос без совпадений

- **GIVEN** проиндексированный проект
- **WHEN** выполняется `desc-search --text "xyzzy qwerty фырц"` (все термины запроса
  вне словаря LSA и не встречаются в описаниях)
- **THEN** возвращён успешный ответ с пустым массивом результатов без ошибки
- **AND** semantic-слой не находит документов для полностью внесловарного запроса

### Requirement: Ранжирование по весам имя/описание

Система SHALL строить полнотекстовый вектор с весами: имя сущности — вес A,
описание — вес B (конфигурация `'russian'`). Совпадение по имени SHALL
ранжироваться выше совпадения той же релевантности только по описанию.

#### Scenario: Имя бьёт описание

- **GIVEN** проект с процедурой `BindClassifier_Main` (совпадение по имени)
  и процедурой с описанием, содержащим слово «bindclassifier» (совпадение по описанию)
- **WHEN** выполняется `desc-search --text "BindClassifier"`
- **THEN** `BindClassifier_Main` ранжирован выше процедуры с совпадением только в описании

### Requirement: Фильтр по kind

Система SHALL поддерживать фильтрацию выдачи по типу сущности: `procedure`,
`service`, `event`, `callback_event`, `used_service`. Без фильтра SHALL
возвращаться совпадения всех типов.

#### Scenario: Только процедуры

- **GIVEN** проект, где запросу соответствуют и процедуры, и контракты
- **WHEN** выполняется `desc-search --text "<запрос>" --kind procedure`
- **THEN** выданы только записи с kind `procedure`

#### Scenario: Несколько kind

- **WHEN** выполняется `desc-search --text "<запрос>" --kind service --kind event`
- **THEN** выданы только записи контрактов типов `service` и `event`

### Requirement: Контракт вытесняет реализующую процедуру

Если процедура связана отношением `implements_contract` с контрактом, у которого
непустое описание, то такая процедура SHALL исключаться из выдачи (контракт
представляет пару). Если описание контракта пустое, процедура SHALL оставаться
в выдаче. Описания при индексации SHALL сохраняться у всех процедур независимо
от наличия контракта.

#### Scenario: Реализация скрыта за контрактом

- **GIVEN** процедура `API_CCred_BindClassifier` (SQL) связана отношением
  `implements_contract` с контрактом `API_CCred_BindClassifier`, чьё описание непусто
- **WHEN** выполняется `desc-search` с запросом, совпадающим с описанием
- **THEN** в выдаче одна запись — контракт (kind `service`)
- **AND** дублирующая запись процедуры (kind `procedure`) отсутствует

#### Scenario: Fallback при пустом описании контракта

- **GIVEN** процедура связана с контрактом, у которого описание пусто
- **WHEN** выполняется `desc-search` с запросом, совпадающим с описанием процедуры
- **THEN** в выдаче присутствует запись процедуры (kind `procedure`)

### Requirement: CLI-команда desc-search

Система SHALL предоставлять команду `codebase query desc-search` с флагами
`--text` (обязательный), `--kind` (повторяемый), `--limit` (по умолчанию —
значение конфигурации). Команда SHALL поддерживать `--json`-envelope
(`success`, `format_version`, `command`, `count`, `items`, `meta`); при пустом
результате SHALL возвращаться `[]` без ошибки.

#### Scenario: JSON-режим

- **WHEN** выполняется `codebase query desc-search --text "<запрос>" --json`
- **THEN** вывод — machine-readable envelope с полями `success`, `command`,
  `count`, `items`
- **AND** при отсутствии совпадений `items` равен `[]`

#### Scenario: Превышение лимита

- **GIVEN** запрос, которому соответствует больше записей, чем `--limit`
- **WHEN** выполняется `desc-search --text "<запрос>" --limit 10`
- **THEN** возвращено не более 10 записей
- **AND** метаданные ответа содержат признак усечения

### Requirement: LSA-модель корпуса описаний

Система SHALL обучать отдельную LSA-модель на корпусе документов описаний:
SQL-процедуры (текст = имя процедуры с двойным весом + header-описание) и
API-контракты (текст = имя контракта с двойным весом + краткое и полное
описание). Спековый корпус и существующая spec-LSA-модель SHALL оставаться
неизменными. Обучение SHALL выполняться в пост-обработке индексации с машиной
переобучения по fingerprint корпуса (переобучить / идемпотентный пропуск /
отложить до порога накопленных изменений); модель SHALL публиковаться
поколениями (generation) с хранением текущего и предыдущего. При корпусе
меньше минимального размера обучение SHALL пропускаться.

#### Scenario: Первое обучение при полной пересборке

- **GIVEN** БД после полной пересборки с заполненными описаниями и отсутствие
  desc-модели
- **WHEN** выполняется пост-обработка индексации
- **THEN** desc-модель обучена, поколение опубликовано, sidecar-файлы
  (модель + состояние) записаны

#### Scenario: Идемпотентный пропуск

- **GIVEN** desc-модель обучена на корпусе с fingerprint F
- **WHEN** повторный прогон без изменений описаний
- **THEN** переобучение не выполняется, состояние помечает модель актуальной

#### Scenario: Спек-модель не затронута

- **GIVEN** обученные spec- и desc-модели
- **WHEN** описания процедур изменились и desc-модель переобучилась
- **THEN** spec-модель и её поколения остались без изменений

### Requirement: Гибридный поиск exact + semantic

Поиск `desc-search` SHALL выполнять запрос в двух слоях: лексическом
(FTS-вектор + trgm) и семантическом (LSA desc-модели), и объединять выдачу.
Семантические хиты SHALL находиться по перефразировкам (термины, отсутствующие
в описании дословно). Каждый хит SHALL помечаться источником (`exact` или
`semantic`) со своим рангом; для semantic-хитов SHALL применяться фильтр
минимального cosine и относительный cutoff от максимума. При отсутствии
обученной desc-модели поиск SHALL возвращать только exact-хиты без ошибки.
Фильтр по kind и правило «контракт вытесняет процедуру» SHALL действовать
на объединённую выдачу.

#### Scenario: Семантический хит по перефразировке

- **GIVEN** обученная desc-модель и процедура, чьё описание описывает
  «возврат сумм из банка-партнёра»
- **WHEN** выполняется `desc-search --text "как вернуть деньги с банковского счёта партнёра"`
- **THEN** процедура найдена как semantic-хит, помеченная источником `semantic`

#### Scenario: Fallback без модели

- **GIVEN** desc-модель не обучена (корпус меньше минимума или первый запуск)
- **WHEN** выполняется `desc-search --text "<запрос>"`
- **THEN** возвращены только exact-хиты без ошибки

#### Scenario: Дедуп на объединённой выдаче

- **GIVEN** процедура, реализующая контракт с непустым описанием, найдена
  в обоих слоях
- **WHEN** формируется выдача
- **THEN** пара представлена одной записью контракта, дублирующие записи
  процедуры отсутствуют

> Примечание: semantic-слой по построению возвращает ближайшие по латентной
> близости документы для терминов, входящих в словарь модели, — «пустой» выдачи
> для частично известных запросов он не даёт (это его назначение). Пустой
> результат возможен, когда все термины запроса вне словаря модели (см.
> сценарий «Запрос без совпадений»).

### Requirement: MCP-инструмент desc-search

MCP-сервер SHALL предоставлять инструмент `codebase_query_desc_search` с
параметрами `text` (обязательный), `kind` (опциональный, повторяемый), `limit`
(опциональный). Большие ответы SHALL пагинироваться штатным механизмом
`codebase_read_more`.

#### Scenario: Вызов через MCP

- **GIVEN** запущенный MCP-сервер с профилем query
- **WHEN** клиент вызывает `codebase_query_desc_search` с `text`
- **THEN** возвращены результаты поиска в формате выдачи `desc-search`

#### Scenario: Пагинация большого ответа

- **GIVEN** запрос с большим числом совпадений
- **WHEN** ответ превышает лимит чанка
- **THEN** ответ помечен как пагинированный с continuation_id
- **AND** повторный вызов `codebase_read_more` возвращает следующую часть

## Related code

- `internal/parser/sql/sql_parser.go` — окно захвата header-описания (декларация → тело, три стиля, чистка, 8 КБ)
- `internal/store/db_fts.go` — векторы `search_vector` (имя A / описание B), бэкфилл контрактов, корпус `LoadDescriptionsForLSA` c фильтром mojibake
- `internal/query/desc_query.go` — гибридный поиск (exact UNION + semantic LSA), дедуп «контракт вытесняет процедуру», kind-фильтр
- `internal/query/desc_embeddings_cache.go` — бинарный кэш эмбеддингов поколения (производительность semantic-слоя)
- `internal/indexer/indexer_postprocess_desc_lsa.go` — обучение desc-модели, машина переобучения, публикация поколений
- `internal/config/config.go` — секция `[desc_lsa]` (sidecar-пути, пороги, дефолты)
- `cmd/query_desc.go` — CLI `query desc-search`
- `internal/mcp/registry.go` — MCP-инструмент `codebase_query_desc_search`

## Notes

- Корпус desc-модели независим от спекового (см. `query/spec-search`): собственные
  sidecar-файлы `desc_lsa_model.bin` / `desc_lsa_state.json`, таблицы
  `desc_vocab` / `desc_embeddings` (см. `infrastructure/database-schema`).
- Правило извлечения описаний процедур описано в `indexing/sql-parsing`
  (требование «Извлечение header-описаний SQL-процедур»).
- Корневой фикс кодировок CP1251/CP866 (часть mojibake-описаний FA) — отдельное
  предложение `Modifications/fix-sql-encoding-detection.md`; в corpus-загрузчике
  применяется фильтр mojibake-документов.
