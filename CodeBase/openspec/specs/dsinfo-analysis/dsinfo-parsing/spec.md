# DsInfo Parsing

## Purpose

Разбор файлов конфигурации развёртывания Diasoft 5NT (условное имя
`DiasoftSystemInfo.csv`) в структурированный снимок: манифест продуктов
«Продукты Digital Q», список BPL/EXE-модулей «Модули» и реестр объектов БД
«Процедуры». Снимок используется для сопоставления конфигурации банка с
проиндексированными релизными линиями продуктов FA.

## Requirements

### Requirement: Определение формата по содержимому

Парсер SHALL определять, что файл является конфигурацией Diasoft SystemInfo, по
содержимому, а не по имени файла: содержимое декодируется из WIN-1251, содержит
маркер секции «Продукты Digital Q» и маркер секции «Модули» с заголовком колонок,
начинающимся с `FileName;`. Файл, не удовлетворяющий признакам, SHALL
отклоняться с ошибкой, указывающей, что файл не похож на конфигурацию Diasoft
SystemInfo.

#### Scenario: Файл с неканоническим именем распознаётся

- **GIVEN** файл с содержимым DiasoftSystemInfo.csv, но с именем `export-2026-09-08.csv`
- **WHEN** выполняется разбор файла
- **THEN** файл распознаётся как конфигурация Diasoft SystemInfo и разбирается

#### Scenario: Посторонний CSV-файл отклоняется

- **GIVEN** CSV-файл с разделителем `;` без маркеров секций «Продукты Digital Q» и «Модули»
- **WHEN** выполняется разбор файла
- **THEN** разбор завершается ошибкой с указанием, что файл не похож на конфигурацию Diasoft SystemInfo
- **AND** никакие данные не сохраняются

### Requirement: Разбор манифеста «Продукты Digital Q»

Парсер SHALL разбирать каждую непустую строку секции «Продукты Digital Q» до
начала следующей секции: часть до `\` SHALL сохраняться как базовая ссылка
(`raw_name`), часть после `\` — как ссылка на установленный пакет (`packet_ref`);
при отсутствии `\` значение `packet_ref` SHALL быть пустым.

#### Scenario: Строка с хотфиксом

- **GIVEN** строка манифеста `FA-Contracts-11-01-7\FA-Contracts-11-01-7-HF008;`
- **WHEN** секция разобрана
- **THEN** базовая ссылка равна `FA-Contracts-11-01-7`
- **AND** ссылка на пакет равна `FA-Contracts-11-01-7-HF008`

#### Scenario: Строка без пакета

- **GIVEN** строка манифеста `FA-GAAP-11-01-4;`
- **WHEN** секция разобрана
- **THEN** базовая ссылка равна `FA-GAAP-11-01-4`
- **AND** ссылка на пакет пуста

### Requirement: Нормализация имени продукта

Для каждой строки манифеста парсер SHALL вычислять нормализованное имя продукта
(`product_name`) — токены базовой ссылки до первого чисто числового токена,
приведённые к нижнему регистру; ключ релизной линии (`branch_key`) — `product_name`
плюс первые три числовых токена; имя хотфикса (`hotfix_name`) — из ссылки на
пакет по суффиксу `-HF<цифры>`, если он присутствует.

#### Scenario: Продукт с хотфиксом

- **GIVEN** строка манифеста `FA-Contracts-11-01-7\FA-Contracts-11-01-7-HF008;`
- **WHEN** вычислены нормализованные значения
- **THEN** имя продукта равно `fa-contracts`
- **AND** ключ линии равен `fa-contracts-11-01-7`
- **AND** имя хотфикса равно `FA-Contracts-11-01-7-HF008`

#### Scenario: Extension-пакет с PKG

- **GIVEN** строка манифеста `FA-Contracts-Ext-9-01-553-PKG-IFRS9_TOYOTA\FA-Contracts-Ext-9-01-553-PKG-IFRS9_TOYOTA-75-26012604;`
- **WHEN** вычислены нормализованные значения
- **THEN** имя продукта равно `fa-contracts-ext`
- **AND** ключ линии равен `fa-contracts-ext-9-01-553`
- **AND** имя хотфикса пусто

### Requirement: Разбор секции «Модули» (BPL/EXE)

Парсер SHALL разбирать строки подсекции BPL/EXE секции «Модули» (строки после
заголовка колонок `FileName;...;Hash` до конца подсекции): имя файла, описание,
имя модуля, четыре компоненты версии продукта, имя пакета установки, имя
хотфикса, дата сборки и хеш файла. Подсекция SHALL определяться по заголовку
колонок, а не по имени секции.

#### Scenario: Модуль с именем пакета

- **GIVEN** строка `D5NTWRD.BPL;;Administrator;11;1;7;7836;FA-Administrator-11-01-7-26072102;;;;;;;;;21.07.2026;D1C625A3;`
- **WHEN** секция «Модули» разобрана
- **THEN** сохранена запись с именем файла `D5NTWRD.BPL`, именем модуля `Administrator`, именем пакета `FA-Administrator-11-01-7-26072102`, датой сборки 21.07.2026

#### Scenario: Пакет указан в HotfixName при пустом PacketName

- **GIVEN** строка модуля с пустым полем PacketName и заполненным HotfixName `FA-MoneyMarket-11-01-3-HF007-25121001`
- **WHEN** строка разобрана
- **THEN** обе ссылки сохранены без взаимных подстановок

### Requirement: Разбор секции «Процедуры»

Парсер SHALL разбирать строки секции «Процедуры» (схема конфигурационного
элемента, имя объекта, дата установки, имя модуля, имя пакета, имя файла
установки, код состояния, статус, комментарий), сохраняя все поля как есть,
включая строки с пустым именем пакета и «нулевые» даты вида `01/01/1900`.
Блоки «Статистика» внутри секции SHALL пропускаться.

#### Scenario: Установленная процедура

- **GIVEN** строка `Fa_Core;XMLMessage_Insert;04/09/2026 22:37:55;Payments;FA-Payments-11-01-21-26082602;XMLMessage_Insert.sql;1;ОК;Не принадлежит...`
- **WHEN** секция «Процедуры» разобрана
- **THEN** сохранена запись с именем объекта `XMLMessage_Insert`, именем модуля `Payments`, именем пакета `FA-Payments-11-01-21-26082602`, кодом состояния 1, статусом `ОК`

#### Scenario: Процедура без сведений об установке

- **GIVEN** строка `Fa_Core;WRN_FillSyncTables;12/06/2015 21:57:51;;;;16;Отсутствует информация...;`
- **WHEN** строка разобрана
- **THEN** запись сохранена с пустыми именами модуля и пакета и кодом состояния 16

### Requirement: Пропуск нерелевантных секций

Парсер SHALL пропускать секции и подсекции, не относящиеся к снимку: «Информация»,
«Параметры системы», «Конфигурация», «Продукты» (внутренние модули с описаниями),
«Установленные пакеты», параметры модулей, «Мапинг функций dssql». Повторная
секция «Модули» с иным форматом колонок («Установленные пакеты») НЕ SHALL
попадать в результаты разбора модулей.

#### Scenario: Повторная секция «Модули» с историей пакетов

- **GIVEN** файл содержит секцию «Модули» с BPL/EXE-строками и позднее вторую секцию «Модули» с подсекцией «Установленные пакеты»
- **WHEN** файл разобран
- **THEN** в результатах разбора модулей присутствуют только BPL/EXE-строки первой секции
- **AND** строки истории установки пакетов не попали ни в один результат

### Requirement: Метаданные развёртывания

Парсер SHALL извлекать из секции «Конфигурация» имя сервера БД и имя базы, а из
секции «Информация» — алиас SQL-сервера, сохраняя их как метаданные снимка;
отсутствие секций или полей НЕ SHALL приводить к ошибке разбора.

#### Scenario: Метаданные заполнены

- **GIVEN** файл содержит «Конфигурация» с именем сервера `RUMOS072VT` и именем базы `testdb2` и «Информация» с алиасом `sql2019_testv`
- **WHEN** файл разобран
- **THEN** метаданные снимка содержат сервер `RUMOS072VT`, базу `testdb2`, алиас `sql2019_testv`

#### Scenario: Секции метаданных отсутствуют

- **GIVEN** файл без секции «Конфигурация»
- **WHEN** файл разобран
- **THEN** разбор завершается успешно, метаданные сервера и базы пусты

- `internal/dsinfo/parser_test.go`, `internal/dsinfo/normalize_test.go` — юнит-тесты на фрагментах реального CSV

## Notes

- Снимок сохраняется как профиль через `dsinfo-analysis/dsinfo-storage`.
- `ModuleName` из секции «Модули» совпадает с `moduleIDMap` в `internal/rti/symbols.go` — задел под маппинг RTI ModuleID → пакет → продукт (изменение `dsinfo-product-branches`).
- Колонки `Addition*`/`PacketVersion*` в реальных файлах всегда пусты и не разбираются; при появлении значений — аддитивное расширение с повышением `ParserVersion`.
