## Why

Код-ревью парсинга OpenSpec и инструментов поиска выявило девять дефектов, из-за которых LSA-индекс может бессрочно сохранять удалённые документы или не восстанавливаться после ошибки, технические идентификаторы и контекст `by-code` находятся неполно, границы строк вычисляются неточно, а документация расходится с фактическим публичным интерфейсом. Исправления нужны, чтобы результаты индексации и поиска соответствовали актуальному корпусу и были диагностируемыми через CLI и MCP.

## What Changes

- Сделать жизненный цикл LSA-модели устойчивым к удалению spec-файлов и незавершённому переобучению, исключив публикацию несогласованных model/state/vocab/embeddings.
- Унифицировать разрешение относительного `lsa_model_path` для индексатора и поискового сервиса.
- Перестроить лексические `tsvector` с весами A/B согласно назначению полей.
- Выполнять trigram-поиск технических идентификаторов по индексируемым выражениям и `spec_code_mentions`, не полагаясь на similarity с длинным агрегированным текстом.
- Возвращать явную диагностику недоступного semantic-слоя в режиме `both` и ошибку в режиме `semantic`, не подавляя ошибки БД или повреждения модели.
- Исправить формирование контекста `spec_by_code` для requirement/scenario/usecase.
- Исправить фактические границы строк delta-требований и сценариев.
- Исправить README и спецификацию поиска: документировать фактические канонические параметры MCP `query` и CLI `--query` без добавления alias в код.
- Добавить регрессионные unit- и integration-тесты для всех исправленных сценариев.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `indexing/openspec-parsing`: границы строк сценариев и delta-требований должны соответствовать фактическим блокам исходного Markdown.
- `query/spec-search`: меняются гарантии актуальности и атомарной публикации LSA, диагностика semantic-ошибок, weighted FTS и поиск технических идентификаторов; контракт CLI/MCP приводится к фактическим параметрам `query`/`--query`.
- `query/spec-queries`: `spec_by_code` должен возвращать непустой matching context для каждого поддерживаемого типа источника спеки.

## Impact

- Код: `internal/indexer/indexer_postprocess_spec_lsa.go`, порядок cleanup/post-processing в `internal/indexer/runner.go`, `internal/specfts`, `internal/store`, `internal/specsvc/specsvc.go`, `internal/parser/openspecmd`; документация: `README.md` и delta-спека поиска.
- Данные: потребуется пересчёт `search_vector`; при следующей индексации может потребоваться безопасное переобучение LSA и замена `spec_vocab`/`spec_embeddings`.
- Интерфейсы: MCP `query` и CLI `--query` остаются единственными параметрами текста поиска; README и спецификация исправляются в соответствии с ними. Формат результата расширяется диагностикой недоступного semantic-слоя без изменения секций `exact`/`semantic`.
- Зависимости: новые внешние библиотеки не требуются; используются PostgreSQL `tsvector`, `pg_trgm`, существующее файловое хранение модели и транзакции БД.
