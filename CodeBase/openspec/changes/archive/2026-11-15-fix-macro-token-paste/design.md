## Context

Раскрытие макросов для review живёт в `internal/review/review_parser.go`:
`collectMacroDefinitions` собирает `#define` (включая `\`-продолжения),
`expandMacrosInLines`/`expandFirstMacroCall` подставляет вызовы,
`applyMacroArguments`/`replaceIdentifierToken` подставляет аргументы в тело.
Сейчас `##` распознаётся только в `findMacroCall`, когда он стоит перед
*именем макроса* (`sp.##M_LOGINTIME`). Для параметра `##` не обрабатывается:
`ch##mx##` после подстановки `mx=1` становится `ch##1##`.

Потребители раскрытого текста (`checkTableFullScan`, `isTableFiltered`,
`extractColumnRefsFromWhere`/`FromOn`) сопоставляют алиас таблицы с
квалифицированными ссылками через `reLookupQualifiedRef = (\w+)\.(\w+)`
(`review_lookup.go:30`). `\w` не включает `#`, поэтому `ch##1##.SPID` не
даёт ссылку на `ch##1##`, и таблица выглядит нефильтрованной. Симптом —
ложный `tableFullScan` в `API_CON_RuleDoc_MassGetLimitAcc.sql:2092`
(см. `proposal.md → Why`).

Ограничение: `##` в кодовой базе — не только token-paste. Это ещё префикс
global temp table (`##GlobalRest`, `##OUTTABLE`), placeholder файла
(`##CURRENT_MODULEID##`), встроенный маркер (`##PPVARCNT##`) и объектные
макросы (`##_SHARED_SEED_##`). Схлопывать можно только `##`, примыкающий к
имени **объявленного параметра** раскрываемого макроса.

## Goals / Non-Goals

**Goals:**
- Подстановка параметра в paste-идиоме даёт цельный идентификатор
  (`ch##mx##` + `mx=1` → `ch1`), сохраняя `SourceMap` (исходные строки).
- Литеральные `##`-имена временных таблиц не искажаются.
- Регрессионный тест воспроизводит 12-веточный `INSERT…SELECT` и
  подтверждает отсутствие ложного `tableFullScan`.

**Non-Goals:**
- Не чиним FN по веткам `union all` №2–12: `extractTablesFromFromClause`
  и `extractColumnRefsFromWhere` по-прежнему смотрят только первый
  `FROM`/`WHERE`. Это отдельный кандидат-последователь.
- Не меняем логику самих правил и `reLookupQualifiedRef`.
- Не трогаем SQL-парсер индексатора (`internal/parser/sql`).

## Decisions

### D1. Паст выполняем в момент подстановки параметра, а не пост-проходом

`applyMacroArguments` уже ходит по телу построчно и по параметрам. Вместо
`replaceIdentifierToken("mx"→arg)` вводим распознавание paste-обёртки вокруг
**объявленного параметра**:

```go
pat := "(?i)(?:##)?\\b" + regexp.QuoteMeta(strings.TrimSpace(param)) + "\\b(?:##)?"
line = cachedRegexp(pat).ReplaceAllLiteralString(line, replacement)
```

Ключевые детали:

- `\b` ставится вокруг **имени параметра**, а не вокруг `##`: границы слова
  защищают от порчи подстрок (`LinkID` при параметре `id` не меняется).
- `(?:##)?` с каждой стороны опционален и поглощается в том же совпадении,
  поэтому `##` не остаётся ни при наличии, ни при отсутствии.
- `regexp.QuoteMeta` — параметр трактуется буквально.
- `ReplaceAllLiteralString` — значение аргумента с `$` не интерпретируется
  как группы замены (в отличие от `ReplaceAllString`).

Проверенная матрица:

| Вход | Результат |
|---|---|
| `ch##mx##`, `mx=1` | `ch1` |
| `mx`, `mx=1` | `1` (прежнее поведение сохраняется) |
| `sb##mx##.SPID` | `sb1.SPID` |
| `@##OBJECT##SeedID`, `OBJECT=User` | `@UserSeedID` |
| `i##__N__##`, `__N__=2` | `i2` |
| `LinkID`, параметр `id` | `LinkID` (без порчи) |
| `##PREFVAR##ObjectID`, пустой аргумент | `ObjectID` (оба `##` поглощены) |
| `##GlobalRest` | без изменений: `GlobalRest` не параметр |

**Почему не буквальный `##?<param>##?`:** это regex «один `#` + необязательный
`#`», он не подставляет обычный `mx` (регрессия базовой подстановки). А
«логический» `(?:##)?<param>(?:##)?` без `\b` портит подстроки.

**Почему не пост-проход по `##`:** глобальное схлопывание `##` необратимо
ломает литеральные temp-имена и плейсхолдеры `##M_TABNAME##`,
`##CURRENT_MODULEID##`, `##PPVARCNT##`. Привязка к объявленному параметру
точно отделяет paste от префикса temp/placeholder.

**Альтернатива (отклонена):** расширить `reLookupQualifiedRef` до
`([\w#]+)\.(\w+)`. Лечит симптом только у правил alias→условие, оставляет
`ch##1##` в раскрытом тексте и маскирует дефект для остальных потребителей.

### D2. Поглощение `##` только примыкающее к объявленному параметру

`##` удаляется лишь как часть совпадения
`(?:##)?\b<param>\b(?:##)?`. `##`, не примыкающий к имени параметра,
не затрагивается: prefix global temp (`##GlobalRest`, `##OUTTABLE`),
placeholder файла (`##CURRENT_MODULEID##`), встроенный маркер
(`##PPVARCNT##`, `@val##PPVARCNT##PPLINE`), объектный макрос
(`##_SHARED_SEED_##`). Если `_TABLENAME_` **объявлен параметром**
конкретного макроса — он схлопывается по общему правилу; если нет —
остаётся как есть. Это делает операцию идемпотентной и безопасной при
повторных проходах `expandMacrosInLines` (до 32 pass'ов): после первой
подстановки `##` вокруг параметра уже нет.

### D5. Область раскрытия — только `#define` текущего файла

Препроцессор review не резолвит `#include` (в `review_parser.go` нет
обработки include; `#include` фиксируется только в правиле
`debugProfileEnabled`). Правка паста не меняет это поведение, но spec MUST
явно фиксировать границу, чтобы не создавать ожидание раскрытия макросов из
`.h`.

### D3. Регрессия — синтетический фикстур + ручная проверка реального файла

Юнит-тест в `review_parser_test.go` на `ch##mx##`/`sb##mx##`/`dk##mx##`
(включая существующий кейс paste перед именем макроса). Интеграционный тест
в `review_rules_test.go` — компактный `INSERT…SELECT` с 12 `union all` через
параметризованный `#define`, проверяющий отсутствие `tableFullScan` и
наличие `ch1…ch12`. Реальный файл (`API_CON_RuleDoc_MassGetLimitAcc.sql`)
прогоняется вручную как smoke; в тестовый набор не тащим из-за размера и
привязки к FA.

### D4. Сегментация операторов не меняется

Якорь `INSERT…SELECT` (строка `insert`) уже обеспечен
`findStatementStartForTableHintExists`/`stmtStartLine`; правка только
устраняет `##` из раскрытого текста, не влияя на границы операторов и
`SourceMap`.

## Risks / Trade-offs

- **Ложный paste на литеральном `##` рядом с параметром** → срабатывает
  только если сам **объявленный параметр** примыкает к `##`; в C-семантике
  это и есть paste, поэтому риск приемлем и покрыт тестами `##GlobalRest`,
  `##CURRENT_MODULEID##`, `##PPVARCNT##`, `##_SHARED_SEED_##`.
- **Пустой аргумент** (`__InterestValue__()` → `ObjectID`) → `(?:##)?` с
  обеих сторон поглощает оба `##` в том же совпадении; без этого получилось
  бы `##ObjectID`/`ObjectID##`. Покрыто тестом.
- **Плейсхолдеры вида `t##__table__##`** → `__table__` не является
  параметром макроса, поэтому не совпадает; сохраняются как есть.
- **Двойная подстановка/рекурсия** → поглощение `##` в том же шаге делает
  операцию идемпотентной; повторные pass'ы не находят `##` вокруг параметра.
- **Скрытые потребители раскрытого текста** → `isTableFiltered`/
  `extractColumnRefs*` использует только `tableFullScan`, но
  `extractTablesFromFromClause`/`parseTableWithAlias` — многие правила.
  Коррекция алиасов должна проверяться baseline-дифом на `USR_GET_*.sql` и
  `WarrantyInterest_*.sql`, а не считаться гарантированно безопасной.
- **Подстановка внутри строковых литералов (pre-existing)** →
  `replaceIdentifierToken` не различает строковые литералы; параметр с
  коротким именем потенциально заменяется внутри `'...'`. Не регрессия
  данного change; фиксируется как известное ограничение и кандидат-последователь.
- **Производительность** → один regex на параметр на строку тела; на
  реальных файлах незаметно (тело макроса мало).
