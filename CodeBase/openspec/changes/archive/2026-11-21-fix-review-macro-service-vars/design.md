## Context

Механика типизации переменных в review (см. proposal.md — Why): `collectVariableTypes` (review_helpers.go:1984) собирает типы из трёх источников — параметры процедур парсера, `declare`-блоки контента, параметры из индекса (`enrichVariableTypesFromAPI` → `lookupProcedureParams`). Контент при этом — результат `replaceMacros`, который раскрывает только `#define` из самого файла; `#include <macros.h>` не резолвится, поэтому `__BEGIN_PROCEDURE__(...)` остаётся текстом, а его декларация `declare @RetVal int, @trancount int` (MACROS.H:1346) недостижима.

Эмпирическая база: из 59 препроцессированных `.t01` в `fa-contracts\Consumer\SERVER\UPLOAD` 47 используют `@RetVal` (13 — tmp/patch-скрипты без него); 43 из этих 47 содержат ровно `declare @RetVal int, @trancount int`; прочие выбросы — форматирование и один `DSINT_KEY` (та же numeric precision 10, что у `int`, на детекцию потери не влияет). PG-стиль `DCL_PROC_BODY` (MACROS.H:751) декларирует другой набор: `@tran_count int, @err_code int, @msg varchar(255)`.

Потребители карты типов — 8 правил: `checkDatatypeFetchInto` (:100), `checkDatatypeSelectAssign` (:189), `checkDatatypeExecParams` (:2641), `checkDateIntoString` (:4922), `checkEmptyStringDate` (:5322), `checkIsNullSameTypes` (:6468), `checkDiffTypesComparison` (:6809), `checkFloatToStringConvert` (:6976) — все в `review_rules.go`.

## Goals / Non-Goals

Goals:

- Правила, использующие карту типов, видят `@RetVal`/`@trancount` (и PG-набор) как `int`/`varchar(255)` в файлах с нераскрытыми `__BEGIN_PROCEDURE__`/`DCL_PROC_BODY`.
- Изменение локализовано в одной центральной точке (`collectVariableTypes`), без БД-lookup'ов и без изменений препроцессинга.

Non-Goals:

- Include-резолвинг `#include <macros.h>` из индекса и раскрытие ядровых макросов (многофайловый SourceMap, `#ifdef`/`#ifndef`, стрингификация `"PROCNAME2 - begin"`) — отдельное изменение, если понадобится.
- Индексация `#define` из `.h`-файлов в symbols.
- Расширение набора сервисных переменных за пределами двух макросов (например, `M_BUSINESSLOG_*`-переменные `@BL__*`, декларируемые в теле файла явными declare — они уже видны).

## Decisions

### D1. Встроенная таблица типов, триггер — текстовое присутствие нераскрытого макроса

В `collectVariableTypes` после сбора declares и до return: если в контенте есть `__BEGIN_PROCEDURE__` — добавить `retval → int`, `trancount → int`; если `DCL_PROC_BODY` — добавить `tran_count → int`, `err_code → int`, `msg → varchar(255)`. Оба макроса могут встретиться в одном файле (маловероятно) — наборы объединяются по правилам D2.

Альтернативы: (a) резолвить типы из определения макроса в индексе — требует индексации defines из `.h`, которой нет; (b) полный include-препроцессинг — см. Non-Goals. Встроенная таблица — константа из MACROS.H, детерминированная и дешёвая; деградирует только при изменении ядрового макроса между версиями (набор стабилен десятилетиями, см. `.t01`).

Детекция: переиспользовать существующий `reBeginProcedure` (review_helpers.go:43, матчит `__BEGIN_PROCEDURE__(name)`) и добавить симметричный regex для `DCL_PROC_BODY\s*\(`. Важно: триггер — макрос в контенте после `replaceMacros`, т.е. файл, самостоятельно определивший и раскрывший макрос, триггером не станет (раскрытый вызов в контенте исчезает).

### D2. Fill-gaps: встроенные типы не перезаписывают источники файла

Заполнение только отсутствующих ключей — тот же контракт, что у `enrichVariableTypesFromAPI` (review_helpers.go:2060). Приоритет: параметры сигнатуры и `declare`-блоки файла > встроенные типы. Защищает самодостаточные patch-файлы (`declare @retVal int` инлайн, найдены в `patch7_2_267.sql`, `patch_dml7_2_382.sql`) и гипотетические локальные переопределения (`declare @msg varchar(1000)`).

Встроенные типы применяются внутри `collectVariableTypes`, то есть до API-enrichment (`enrichVariableTypesFromAPI` вызывается правилами позже), поэтому для пяти сервисных имён API-fallback из индекса недостижим — принято сознательно: по данным FA `@RetVal` как параметр сигнатуры в индексе практически не встречается (все найденные объявления — declare-блоки в файлах), а параметры сигнатуры самого файла приоритетны и так.

### D3. Точка встраивания — чистая функция collectVariableTypes

Не Runner-метод, не отдельный проход: все 8 правил получают эффект автоматически, тесты — напрямую на `collectVariableTypes` (в тестовом пакете уже есть unit-тесты этой функции). БД и кэши не задействованы.

### D4. Тип `int`, не `DSINT_KEY`

Выброс `.t01` с `@RetVal DSINT_KEY` показывает вариативность между версиями ядра, но `int` и `DSINT_KEY` эквивалентны по numericPrecisionScale (10,0) — детекция потерь не зависит от выбора. `int` — каноничное написание из MACROS.H:1348.

## Risks / Trade-offs

- [FP в правилах-потребителях кроме `datatype` (`dateIntoString`, `emptyStringDate`, `isNullSameTypes`, `diffTypesComparison`, `floatToStringConvert`)] → приёмка на реальных файлах FA: прогон до/после, дифф по правилам; ожидаемо мало (типичные использования `@RetVal` — `= 0`, `<> 0`, `= кодОшибки`, `isNull(@RetVal, 0)` — не паттерны этих правил). Каждое новое срабатывание оценивается как TP/FP; при систематическом шуме — точечное подавление в конкретном правиле, не откат механизма.
- [Расхождение встроенной таблицы с изменившимся ядровым макросом] → таблица — константа с комментарием-ссылкой на MACROS.H; проверяется по `.t01` при suspicion. Риск принят: набор стабилен.
- [Файл, где `@RetVal` используется с иной семантикой без макроса] → триггер требует присутствия макроса в контенте; без него поведение неизменно (сценарий 5 дельты).
