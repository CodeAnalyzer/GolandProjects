# dsinfo-parser: парсер DiasoftSystemInfo.csv и управление профилями развёртывания

## Why

Анализ инцидентов FA требует знания фактической конфигурации банка: у разных
продуктов одновременно установлены разные релизные линии (Contracts 11.01.7+HF008,
GAAP 11.01.4, Payments 11.01.21+HF004), и без этого анализа enrichment RTI/TRC
сопоставляет процедуры с кодом не той версии. Конфигурация приходит вместе с
задачей в виде CSV-файла (условное имя `DiasoftSystemInfo.csv`, WIN-1251, ~14 МБ,
~70 тыс. строк), который сейчас никак не разбирается.

Это первая, вспомогательная часть изменения
`Modifications/dsinfo-product-branches-6f2a1c.md`: парсер, хранилище и команды
управления профилями — без интеграции в `query`/`rti`/`trc` (проброс `--dsinfo`
выполняется позже отдельным изменением). Парсить нужно уже сейчас: секция
«Модули» файла даёт маппинг `ModuleName → продукт + пакет`, имена модулей
побайтово совпадают с `moduleIDMap` RTI-парсера, а секция «Процедуры» (~62,6 тыс.
строк) — точный снимок «процедура → пакет» для будущего резолва.

## What Changes

- **Новый парсер `DiasoftSystemInfo.csv`** (пакет `internal/dsinfo`):
  потоковое чтение WIN-1251, сниффинг по содержимому (имя файла не канонично),
  разбор секций «Продукты Digital Q», «Модули» (BPL/EXE) и «Процедуры»
  (объекты БД), нормализация `raw_name → product_name/branch_key/hotfix_name`.
- **Схема БД**: таблицы `dsinfo` (профиль: метаданные файла, БД банка,
  счётчики), `dsinfo_products` (манифест «Продукты Digital Q» — снимок без FK на
  ветки), `dsinfo_modules` (BPL/EXE с PacketName/HotfixName), `dsinfo_procedures`
  (снимок процедур БД банка), `dsinfo_state` (singleton активного профиля).
- **Идемпотентный parse**: повторный разбор того же файла возвращает существующий
  профиль по `file_hash + parser_version` (по образцу RTI/TRC-сессий);
  `use_count` не вводится — парсинг дешёвый, профиль — единственный снимок.
- **CLI `codebase dsinfo`**: `parse <file>`, `list`, `show <id>`, `delete <id>`,
  `use <id>` (активный профиль). `show` не выводит 62 тыс. процедур целиком —
  только через фильтры `--module/--packet/--search` с `--limit`.
- **MCP-инструменты** `dsinfo_parse/list/show/delete/use` — те же операции для
  агентов.
- **Не меняется**: поведение `query`/`rti`/`trc` без `--dsinfo` (флага пока нет
  вообще), `init`/`update`, схема существующих таблиц.

## Capabilities

### New Capabilities

- `dsinfo-analysis/dsinfo-parsing`: разбор CSV конфигурации Diasoft — сниффинг
  по содержимому, потоковое чтение WIN-1251, секции «Продукты Digital Q» /
  «Модули» / «Процедуры», правила нормализации имён продуктов и пакетов.
- `dsinfo-analysis/dsinfo-storage`: сохранение профилей с reuse по hash,
  listing, просмотр с фильтрами, удаление, активный профиль (`dsinfo use`),
  CLI- и MCP-команды `dsinfo`.

### Modified Capabilities

(нет — интеграция `--dsinfo` в запросы и enrichment будет отдельным изменением)

## Impact

- **Код**: новые `internal/dsinfo/`, `internal/dsinfosvc/`, `cmd/dsinfo.go`,
  `internal/store/ds_info_store.go`; правки `internal/store/db_schema.go`
  (аддитивные `CREATE TABLE IF NOT EXISTS`), `cmd/root.go` (регистрация
  команды), `internal/mcp/` (5 инструментов), `README.md`.
- **Схема БД**: 5 новых таблиц, каскадное удаление от `dsinfo`; существующие
  таблицы не затрагиваются.
- **Зависимости**: новых внешних нет (декодер WIN-1251 уже есть в
  `internal/encoding`); регистрация в `db_reset.go` при необходимости TRUNCATE.
- **Объём данных**: один профиль ≈ 63 тыс. строк (62,6 тыс. процедур + ~200
  модулей + 62 продукта) — сопоставимо с уже хранимыми RTI/TRC-сессиями.
- **Совместимость**: полностью аддитивно; без вызова `dsinfo` поведение системы
  не меняется.
