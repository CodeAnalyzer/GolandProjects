## ADDED Requirements

### Requirement: Кеш вытесняющих контрактов semantic-слоя

Множество процедур, вытесняемых из semantic-выдачи контрактами с непустым
описанием, SHALL вычисляться не чаще одного раза в рамках неизменного состояния
данных — определяемого парой «поколение модели корпуса описаний + эпоха
индексации (последний завершённый прогон init/update)». Вычисление выполняется
при первом semantic-вызове после старта процесса или изменения любого из двух
компонентов; повторные вызовы при неизменных компонентах MUST NOT повторять
SQL-выборку вытесняемых процедур. Проверка актуальности MUST быть дешёвой (без
пересчёта множества). Состав результатов поиска при актуальном кеше MUST
оставаться идентичным поиску с выборкой на каждом вызове.

#### Scenario: Повторный вызов не выполняет выборку вытеснения

- **GIVEN** загруженная модель корпуса описаний и два последовательных semantic-вызова desc-search в одном процессе без прогонов индексации между ними
- **WHEN** выполняется второй вызов
- **THEN** выборка вытесняющих контрактов из БД не выполняется (используется кеш)
- **AND** результаты обоих вызовов идентичны

#### Scenario: Update без переобучения модели перестраивает кеш

- **GIVEN** в процессе закэшировано множество вытеснения поколения G1 и эпохи индексации R1
- **WHEN** завершён `codebase update`, изменивший контракты или их описания (новая эпоха R2), а модель корпуса НЕ переобучена (fingerprint неизменен)
- **THEN** semantic-вызов перевычисляет множество вытеснения для R2 без участия кеша R1
- **AND** выдача отражает актуальные контракты и рёбра implements_contract

#### Scenario: Смена поколения модели перестраивает кеш

- **GIVEN** в процессе закэшировано множество вытеснения поколения G1
- **WHEN** модель корпуса переобучена на поколение G2 и выполняется semantic-вызов
- **THEN** множество вытеснения перевычисляется для G2 и применяется к выдаче

#### Scenario: Состав выдачи идентичен per-call вычислению

- **GIVEN** БД с контрактами, имеющими непустые описания, и реализующими их процедурами
- **WHEN** semantic-поиск выполняется с актуальным кешем и с выборкой на каждый вызов
- **THEN** процедуры, вытесняемые контрактами, отсутствуют в semantic-выдаче в обоих режимах
