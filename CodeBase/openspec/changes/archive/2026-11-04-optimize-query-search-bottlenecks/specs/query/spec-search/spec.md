## ADDED Requirements

### Requirement: Использование GIN-индексов лексическим слоем

Лексический tsvector-поиск по спекам SHALL применять предикат полнотекстового
совпадения внутри каждой ветки объединения таблиц сущностей
(capabilities/requirements/scenarios/usecases), чтобы планировщик использовал
GIN-индексы `idx_spec_*_fts` и НЕ читал таблицы сущностей целиком. Состав
результатов и ранжирование MUST оставаться идентичными поиску с внешним
предикатом (изменение — только план выполнения).

#### Scenario: План FTS-поиска использует GIN-индексы

- **GIVEN** проиндексированная БД со спеками (десятки тысяч сущностей) и GIN-индексами `idx_spec_*_fts`
- **WHEN** выполняется лексический поиск по фразе из spec-корпуса и анализируется план запроса
- **THEN** план содержит Bitmap/Index Scan по GIN-индексам tsvector, а не Seq Scan по таблицам сущностей
- **AND** CTE объединения сущностей не материализует полный набор строк всех уровней

#### Scenario: Результаты идентичны прежнему составу

- **GIVEN** проиндексированная БД и набор поисковых фраз
- **WHEN** поиск выполняется до и после изменения плана
- **THEN** для каждой фразы возвращается то же множество артефактов с теми же рангами и очерёдностью

#### Scenario: Интерактивная задержка exact-слоя

- **GIVEN** индекс масштаба FA (58 тыс. spec-артефактов)
- **WHEN** выполняется `spec_search` со слоем exact по фразе из корпуса
- **THEN** ответ возвращается за интерактивное время (единицы сотен миллисекунд), без многосекундных задержек на полное чтение таблиц

### Requirement: Гейтинг trgm-поиска по форме запроса

Лексический слой SHALL применять trgm-similarity-поиск по текстовым полям
артефактов (body_text, тексты сценариев, описания usecases) только для коротких
запросов — содержащих не более двух слов-токенов (лексическая единица:
последовательность букв, цифр и подчёркиваний длиной не менее двух, содержащая
хотя бы одну букву — то же правило распознавания слов, что у гейта
лексического покрытия semantic-слоя). Для более длинных фраз similarity-поиск
по текстовым полям MUST пропускаться: он не даёт совпадений из-за асимметрии
длины, но требует многосекундной обработки десятков тысяч кандидатов.
Технические пути поиска MUST выполняться для любых запросов: точное
регистронезависимое сравнение `mention_name`, trgm по `mention_name` и
`related_code`. Слой `exact` интерфейсов CLI/MCP SHALL документироваться как
лексический слой — tsvector + tech-name trgm (без переименования значений
`exact|semantic|both`).

#### Scenario: Многословная фраза не запускает body-trgm

- **GIVEN** проиндексированные спеки и запрос «массовое создание плановых событий» (5 слов)
- **WHEN** выполняется поиск со слоем exact или both
- **THEN** trgm-similarity по body_text/сценариям/usecases не выполняется
- **AND** tsvector-совпадения возвращаются без изменения состава

#### Scenario: Короткий запрос сохраняет полный trgm

- **GIVEN** проиндексированные спеки с техническим именем `FCD_GL_Audit_Insert`
- **WHEN** выполняется поиск со слоем exact по запросу «Audit_Insert» (одно слово-токен с подчёркиванием)
- **THEN** tech-name пути (точное совпадение mention_name, trgm по related_code и mention_name) выполняются и находят артефакты

#### Scenario: Документация слоя exact

- **GIVEN** описания CLI-флага `--layer` и MCP-параметра `layer` инструмента `codebase_query_spec_search`
- **WHEN** пользователь читает справку
- **THEN** слой exact описан как «лексический: полнотекстовый tsvector + trgm по техническим именам и code mentions», без обещания «только точные совпадения»
