## ADDED Requirements

### Requirement: Индексный план трёхполевого поиска report_form

Fallback-поиск символов отчётных форм по трём полям (имя отчёта, имя DFM-формы,
класс DFM-формы) SHALL выполняться индексными ветками поиска по каждому полю
отдельно, а не единым условием-дизъюнкцией, чтобы план использовал индексы
(`idx_symbols_symbol_name_type_lower`, индексы `report_forms`) и НЕ перебирал
все символы типа `report_form`. Состав результатов MUST оставаться прежним:
точное сравнение без учёта регистра по любому из трёх полей, дедупликация копий
из веток без изменений.

#### Scenario: Холодный поиск report_form без таймаута

- **GIVEN** мультиветочный индекс масштаба FA (тысячи символов report_form) и холодный кеш БД
- **WHEN** выполняется `query symbol --name FormRepBCHPeriod --type report_form`
- **THEN** результат возвращается за интерактивное время, без многосекундного ожидания и без обрыва по таймауту MCP

#### Scenario: План не перебирает все report_form-строки

- **GIVEN** проиндексированная БД
- **WHEN** анализируется план трёхполевого поиска по точному имени
- **THEN** план использует точечные index scan по каждому из трёх полей (или их объединение), без скана всех строк типа `report_form` и подзапроса к каждой из них

#### Scenario: Результаты трёхполевого поиска не меняются

- **GIVEN** проиндексированный проект с отчётными формами, использующими DFM-форму `FormRepBCHPeriod`
- **WHEN** выполняется `query symbol --name FormRepBCHPeriod --type report_form` после изменения плана
- **THEN** возвращены те же символы report_form (по имени отчёта, имени и классу DFM-формы), с прежней дедупликацией по продуктам и веткам
