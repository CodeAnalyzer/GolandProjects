## ADDED Requirements

### Requirement: ANALYZE после индексации

После успешного завершения прогона `init` или `update` система SHALL выполнять
`ANALYZE` таблиц кодовой базы, изменяемых индексацией (включая `symbols`,
`query_fragments`, `relations`, `sql_tables`, `sql_procedures`, `files`), чтобы
статистика планировщика соответствовала данным после массовых вставок и
удалений. ANALYZE выполняется вне транзакций прогона; ошибка ANALYZE MUST NOT
проваливать результат прогона — фиксируется предупреждение в лог, данные
индекса остаются зафиксированными. Команды, не изменяющие данные (query, stats,
health, review, mcp), MUST NOT выполнять ANALYZE.

#### Scenario: Update обновляет статистику планировщика

- **GIVEN** БД с устаревшей статистикой после массового инкрементального update
- **WHEN** выполняется `codebase update` с изменёнными файлами
- **THEN** прогон завершается успешно, статистика таблиц кодовой базы обновлена (pg_stat_user_tables.last_analyze заполнен свежей датой)

#### Scenario: Ошибка ANALYZE не проваливает прогон

- **GIVEN** завершившийся индексационный прогон и ANALYZE, завершающийся ошибкой (например, отмена по контексту)
- **WHEN** фиксируется результат прогона
- **THEN** прогон считается успешным, данные индекса зафиксированы
- **AND** в лог записано предупреждение об ошибке ANALYZE

#### Scenario: Read-only команда не выполняет ANALYZE

- **GIVEN** БД с проиндексированным проектом
- **WHEN** выполняется `codebase query symbol --name MyProc`
- **THEN** статистика таблиц не обновляется (last_analyze не меняется)
