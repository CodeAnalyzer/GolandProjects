## ADDED Requirements

### Requirement: Warm-up probe при старте сервера

MCP-сервер SHALL при старте (после построения registry инструментов и до входа в цикл обработки запросов) запускать фоновую горутину warm-up probe для профиля `query`: последовательность реплей-вызовов tool-хендлеров из собранного registry с дешёвыми представительными аргументами. Probe SHALL быть асинхронным (не блокировать MCP-хендшейк и первые запросы) и best-effort: ошибка отдельной пробы не влияет на сервер и остальные пробы, а только фиксируется в логе. Probe SHALL использовать общий таймаут на всю пачку проб из `warmup_timeout_sec` (см. `infrastructure/configuration`). Probe SHALL запускаться только при включённом логировании (logger != nil); при отключённом логировании probe не запускается. Probe не SHALL писать в stdout (транспортный контракт MCP не меняется) и не SHALL изменять результаты tool-вызовов. Пробы SHALL идти в порядке: семантические поисковые пробы (прогрев ленивых LSA/embeddings-кэшей) → проба обхода графа вызовов (прогрев полос листьев индексов графа связей и PK-касований процедур/файлов) → лёгкие пробы поиска по имени; тяжёлые FTS-пробы по query_fragments идут последними либо исключаются. Состав и аргументы проб — константы в коде (одно место правки).

#### Scenario: Асинхронный запуск не блокирует хендшейк

- **GIVEN** запущенный MCP-сервер профиля `query` с включённым логированием
- **WHEN** клиент выполняет initialize и первый tools/call
- **THEN** сервер отвечает без задержки на время работы warm-up probe
- **AND** probe работает параллельно в фоне

#### Scenario: Ошибка пробы не ломает сервер

- **GIVEN** warm-up probe, в котором аргументы одной из проб не находят данных (или хендлер возвращает ошибку)
- **WHEN** probe доходит до этой пробы
- **THEN** ошибка фиксируется в логе
- **AND** оставшиеся пробы выполняются
- **AND** сервер продолжает работать без изменений

#### Scenario: Общий таймаут пачки

- **GIVEN** конфигурация с `[mcp] warmup_timeout_sec = 60`
- **WHEN** суммарное время проб превышает 60 секунд
- **THEN** невыполненные пробы прекращаются по контексту таймаута
- **AND** в логе фиксируется завершение probe с числом выполненных проб и ошибок

#### Scenario: Отключённое логирование — probe не запускается

- **GIVEN** MCP-сервер запущен с logger == nil (логирование отключено)
- **WHEN** сервер стартует
- **THEN** warm-up probe не запускается
- **AND** сервер работает как до доработки

#### Scenario: Профиль без проб — no-op

- **GIVEN** MCP-сервер запущен с профилем, для которого список проб пуст (например, `review`)
- **WHEN** сервер стартует
- **THEN** warm-up probe завершается без единого вызова хендлера (no-op)

#### Scenario: Прогрев снижает цену первого вызова

- **GIVEN** сервер профиля `query` с завершённым (успешно или по таймауту) warm-up probe
- **WHEN** клиент выполняет первый вызов семантического поиска или обхода графа вызовов
- **THEN** длительность первого вызова существенно ниже холодного старта без probe (LSA/embeddings-кэши уже загружены, полосы индексов прогреты)

#### Scenario: Отключение через конфиг

- **GIVEN** конфигурация с `[mcp] warmup_enabled = false`
- **WHEN** MCP-сервер стартует
- **THEN** warm-up probe не запускается и в логе отсутствуют warm-up записи
