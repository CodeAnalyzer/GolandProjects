# Дельта: review/sql-preprocessing

## ADDED Requirements

### Requirement: Идентификация макросов с Unicode-именами

Система SHALL распознавать имена `#define`-макросов и границы их вызовов по
правилам Unicode-идентификаторов. Имя макроса MUST сканироваться до первого
символа, не являющегося буквой любого алфавита, цифрой или `_`; параметры в
скобках после полного имени MUST извлекаться. Проверки границ вызова MUST
считать не-ASCII буквы и цифры частью идентификатора: `_`, примыкающий к букве
не-ASCII алфавита, MUST NOT распознаваться как самостоятельный вызов макроса с
именем `_`. Усечение имени на не-ASCII букве (декларация `_ЦелоеПолож_…`,
распознанная как макрос `_`) MUST NOT возникать; одноимённые декларации MUST
создавать один макрос, а не дубликаты в списке сканирования. Поведение для
макросов с ASCII-именами MUST оставаться неизменным, кроме вхождений,
примыкающих к буквам или цифрам не-ASCII алфавита (ранее такие вхождения
ложно распознавались как вызовы).

#### Scenario: Кириллический макрос раскрывается с параметрами

- **GIVEN** `#define _ЦелоеПолож_(_InpValue_)` с многострочным телом через continuation `\` и вызов `_ЦелоеПолож_(X)` в коде
- **WHEN** выполняется review файла
- **THEN** вызов раскрыт: аргумент `X` подставлен в тело, якорь finding'а указывает на строку вызова
- **AND** строки декларации вырезаны из раскрытого текста
- **AND** в раскрытом тексте нет вставок остатков имён других макросов

#### Scenario: Подчёркивание внутри кириллического слова не является вызовом

- **GIVEN** файл с `#define _Цело_(_InpValue_)` и идентификатор `Х_Цело_` в коде, где `_Цело_` — часть большего слова
- **WHEN** выполняется раскрытие макросов
- **THEN** `Х_Цело_` сохраняется без изменений
- **AND** вхождения `_`, примыкающие к кириллическим буквам, не раскрываются

#### Scenario: Множество кириллических деклараций не коллапсирует в макрос `_`

- **GIVEN** файл с несколькими `#define _<РазныеКириллическиеИмена>_(…)`, включая многострочные тела
- **WHEN** выполняется парсинг деклараций
- **THEN** каждая декларация распознаётся своим полным именем
- **AND** макроса с именем `_` не существует, каскадных подстановок не возникает

#### Scenario: ASCII-макросы обрабатываются как раньше

- **GIVEN** файл только с ASCII-`#define` (параметризованные, token-paste, многострочные continuation), имена макросов не примыкают к буквам/цифрам не-ASCII алфавита
- **WHEN** выполняется review файла до и после изменения
- **THEN** findings эквивалентны по rule/line (0 добавлено, 0 удалено)

#### Scenario: ASCII-имя внутри большего не-ASCII идентификатора не раскрывается

- **GIVEN** `#define M_X(a) ...` и в коде вхождение `ЦелоM_X(1)`, где имя макроса примыкает слева к кириллической букве
- **WHEN** выполняется раскрытие макросов
- **THEN** вхождение не раскрывается — оно часть большего идентификатора

### Requirement: Ограничение роста раскрытия макросов

Раскрытие макросов MUST ограничиваться бюджетом роста: при превышении
установленных пределов (лимит строк и лимит байт на исходную строку)
дальнейшее раскрытие этой исходной строки MUST останавливаться, а частично
раскрытый текст MUST передаваться правилам (fail-open): обработка файла MUST
завершаться за конечное время без зависания. Срабатывание ограничения MUST
фиксироваться в результате раскрытия макросов (флаг и счётчик затронутых
строк) для диагностики. Файлы, раскрытие которых укладывается в бюджет, MUST
обрабатываться с неизменным результатом.

#### Scenario: Саморекурсивный многострочный макрос не вешает review

- **GIVEN** синтетический файл с `#define _A_(_x_)`, тело которого из 2+ строк содержит собственный вызов `_A_(…)`
- **WHEN** выполняется review файла
- **THEN** обработка завершается за конечное время (зависания нет)
- **AND** флаг срабатывания ограничения выставлен, счётчик затронутых строк не меньше 1

#### Scenario: Виснущие файлы ExportToXml/Delta_XML завершаются

- **GIVEN** файлы fa-reports DSArchitectData семейства ExportToXml/Delta_XML с кириллическими макросами, зависавшие до изменения
- **WHEN** выполняется review каждого файла
- **THEN** каждый файл завершает обработку и формирует findings

#### Scenario: Корпус без патологий не затронут бюджетом

- **GIVEN** корпус файлов без кириллических `#define` и без патологий раскрытия
- **WHEN** выполняется review корпуса до и после изменения
- **THEN** findings эквивалентны (0 добавлено, 0 удалено)
- **AND** счётчик срабатываний бюджета равен нулю
