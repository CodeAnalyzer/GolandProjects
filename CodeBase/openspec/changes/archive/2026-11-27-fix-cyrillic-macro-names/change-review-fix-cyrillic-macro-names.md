## 3. Замечания

### F1 (Medium) — tasks 1.2: синтетика не гарантирует экспоненту

`expandFirstMacroCall` раскрывает **один** вызов на строку за проход. Если
тело из 2 строк содержит собственный вызов только в одной, рост линейный
(+1 строка за проход, ≤32 прохода) — текущая сборка **не виснет**, red будет
только из-за отсутствия поля `GuardTripped` (ошибка компиляции), а не по сути.
Экспонента 2^k требует вызова в **каждой** строке тела.

Резолюция: правка tasks 1.2 — указать форму тела
`#define _A_(_x_) _A_(_x_) + 1 \`` / `_A_(_x_) + 2`, и собственный таймаут
теста (goroutine + select), чтобы red = падение, а не глобальный timeout
`go test` (на текущей сборке 2^32 → OOM за секунды).

### F2 (Medium) — tasks 5.2 / 4.2: нет критерия «guard не сработал на 36 файлах»

Если после D1-D3 бюджет срабатывает на кириллических файлах, висяга исчезает,
но остаточный дефект идентификации маскируется: findings остаются
полу-мусорными, а приёмка «файл завершился» — пройдена.

Резолюция: правка tasks 5.2 — добавить явный критерий
`GuardTrippedLines == 0` на всех 36 файлах; срабатывание = дефект, а не
«обработано».

### F3 (Low-Medium) — tasks 5.3: эквивалентность вырождается до 9 файлов

Проверено: mixed45 содержит все 36 кириллических файлов (36/45 по basename).
«mixed45 минус 36» = 9 файлов — слишком мало для claims «эквивалентность».

Резолюция: правка tasks 5.3 — основным контуром считать dq228 − 36 (192 файла,
п.5.4), 5.3 переформулировать как «оставшиеся 9 файлов mixed45» или слить с 5.4.

### F4 (Low) — design Risks: тезис о самосогласованности при ошибочном декоде неверен

Review читает файл с **принудительным** CP866 (`encoding.ReadFile` меняет
кодировку только по BOM/UTF-16; эвристики CP866/CP1251 нет). CP1251-файл с
кириллицей декодируется в mojibake с **не-буквенными** символами. Стенд:
`_ЦелоеПолож_` → `_ЏҐ«®ҐЇ®¦_`, D1-скан останавливается на `«` → имя `_ЏҐ`,
параметры потеряны — та же патология усечения (имена с общим префиксом
коллапсируют). Ограничивает её бюджет D4, а не «побайтовое совпадение».

Резолюция: правка формулировки риска — «при ошибочном декоде имя MAY
усекаться на не-буквенном mojibake-символе; патология ограничивается бюджетом
(D4)». Для 36 файлов DSArchitectData (CP866) неприменимо — там имена
декодируются корректно.

### F5 (Low) — spec: «MUST NOT превышать пределов» не соответствует D4

Проверка после прохода принимает `nextLines` целиком, поэтому результат может
превысить лимит на рост одного прохода (≤ лимит × число строк тела). Это
верно по замыслу (легитимное одиночное раскрытие большого тела сохраняется
целиком), но противоречит буквальному «MUST NOT превышать».

Резолюция: правка требования — «раскрытие одной исходной строки MUST
останавливаться, когда число строк или объём текста превышает предел».

### F6 (Low) — spec: «ASCII-макросы обрабатываются как раньше» слишком сильно

D2 меняет поведение для ASCII-имени, примыкающего к не-ASCII букве/цифре
(раньше ложно матчилось, теперь корректно нет). Это желаемое изменение, но
требование нужно смягчить, иначе любой такой кейс — формальное нарушение спеки.

Резолюция: правка — «…MUST оставаться неизменным, кроме случаев примыкания
к буквам/цифрам не-ASCII алфавита». Эквивалентность 0/0 на корпусе
подтверждается п.5.3/5.4.

### F7 (Info) — 32-проходный кап остаётся вторым «тихим» путём усечения

Если 32 прохода исчерпаны при `changedAny == true`, раскрытие обрезается без
маркера. Тот же диагностический смысл, что и бюджет. Стоимость — одна строка.

Резолюция: рекомендуется включить в D5/D6: маркер выставляется и при
исчерпании проходов с незавершёнными изменениями. Не блокирует.

### F8 (Info) — `\b` в `replaceIdentifierToken` — ASCII-границы

Для кириллических макросов с кириллическими параметрами подстановка имеет ту
же слепоту (`Х_ВхЗнач_` → подставится). Явный Non-Goal design (параметры в
корпусе ASCII — `_InpValue_`).

Резолюция: без правки. В 5.2 при классификации дельт достаточно одного
взгляда, что параметры всех 36 файлов ASCII (одним grep по `#define`).

## 4. Итог

Change к реализации готов после правки tasks (F1-F3) и формулировок design/spec
(F4-F6); F7 — по желанию, F8 — принять. Архитектурных возражений нет: D1-D3
бьют точно в три ASCII-слепых места, D4 — независимый предохранитель, D5/D6
аддитивны и не меняют внешний API.
