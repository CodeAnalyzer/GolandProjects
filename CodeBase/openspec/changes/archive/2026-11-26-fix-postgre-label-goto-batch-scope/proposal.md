# fix-postgre-label-goto-batch-scope

## Why

Правило `postgreLabelGotoLevel` даёт массовый ложный шум: на корпусе fa-generalledger (2946 файлов с `goto`, прогон одним правилом через `--files`) из 39 findings 37 (95%) — кросс-батчевые FP, где «метка выше перехода» на самом деле принадлежит другой процедуре того же файла. Причина — метки собираются в `labels map[string][]int` на весь файл без учёта области видимости, а в T-SQL метка видима только в своём батче (сегмент между разделителями `go`). Генерённый Diasoft-стиль «каждая процедура завершается меткой `_FINISH:`/`_EXIT:`/`_NEXT:`» превращает любой файл с ≥2 такими процедурами в источник FP (пример: `Trunc_Inst.sql:103` — реальная метка `_FINISH:` на 109-й строке ниже перехода, а finding сработал по чужой метке из первой процедуры на 55-й).

## What Changes

- Сопоставление `goto` ↔ метка в `checkPostgreLabelGotoLevel` ограничивается батчем: строка, равная `go` (после зачистки комментариев, Trim, без учёта регистра; также допускается форма `go N`), начинает новый батч; метки предыдущих батчей больше не дают finding для goto последующих батчей.
- Дополнительная граница батча — вызов макроса-завершителя процедуры `ARC_PROC_END(имя)`/`DCL_PROC_END(имя)`/`PROC_END(имя)` (раскрываются в `go` через `#include`-заголовки, которые replaceMacros не резолвит; обязательная скобка отличает вызов от метки `PROC_END:`). Добавлено по итогам code-review R1: оба findings, остававшиеся после `go`-скопинга в `archiver.sql` (215, 406), — кросс-процедурные FP того же класса (границы процедур в файле заданы `ARC_PROC_END` из `archive.h`).
- Ожидаемый эффект на fa-generalledger: 39 → 0 findings (все кросс-процедурные FP, включая остаточные в archiver.sql); на `Trunc_Inst.sql` одиночный review — 0 findings.
- Требование «Использование GOTO и меток» (`review/postgre-requirements`) уточняет формулировку: правило обнаруживает обратный переход к метке, расположенной **в том же батче** выше оператора `GOTO` (текущая широкая формулировка «использование GOTO и меток» расходилась с фактическим поведением — forward-goto с меткой ниже никогда не давал finding, что закреплено тестом `label below goto - ok`).

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `review/postgre-requirements`: требование «Использование GOTO и меток» — добавляется батч-скопинг сопоставления меток и точная формулировка триггера (метка выше перехода в том же батче); сценарий «GOTO в процедуре» уточняется, добавляются сценарии кросс-батчевой невидимости меток.

## Impact

- Код: `internal/review/review_rules.go` — только `checkPostgreLabelGotoLevel` (батч-трекинг в существующем построчном сканере: `reGoBatchSeparator` + `reProcEndMacroSeparator`; зачистка комментариев не меняется).
- Тесты: `internal/review/review_rules_test.go` (новые table-driven кейсы, включая макросы-разделители), `internal/review/review_block_comment_test.go` (кейс `go` внутри блочного комментария не разделяет батчи).
- Спека: `openspec/specs/review/postgre-requirements/spec.md` (дельта через change).
- Документация: строка правила в `README.md` (раздел review) — уточнение формулировки при необходимости.
- Совместимость: без ломающих изменений; меняется только количество findings (FP устраняются), формат finding (rule/severity/message/object) не меняется.
