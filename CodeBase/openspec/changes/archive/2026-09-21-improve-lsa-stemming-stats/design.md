# Design: improve-lsa-stemming-stats

## Context

Токенизация LSA (`internal/specfts/tokenizer.go`) стеммит русские слова самописным однопроходным списком окончаний `stemRussian`. Список дыряв (-ым/-им отсутствуют — формы остаются целыми словами) и содержит опасные короткие суффиксы (-го/-му вспарывают родительный/дательный падеж прилагательных, порождая несуществующие стемы «автоматическо»/«автоматическу»). Проверки длины считаются байтами (`len`), а кириллица в UTF-8 — 2 байта на символ: фильтр аббревиатур «≤ 4 символов» фактически ловит ≤ 2 кириллических букв («США» уходит в стемминг и превращается в «сш»), минимальная длина стема «2» — это 1 символ. Словарь LSA из-за этого фрагментирован: одна лексема = 4-6 строк `spec_vocab` с размазанным doc_freq и завышенным IDF у осколков.

Метрики `stats` (`internal/store/db_stats.go`) считают `spec_vocab`/`spec_embeddings` через `COUNT(*)` без фильтра по `generation`, при этом `DeleteSpecLSAGenerationsExcept` штатно удерживает current + previous поколения — суммы удваиваются и не отражают размер активного словаря.

## Goals / Non-Goals

**Goals:**

- Одна лексема русской парадигмы — один стем и одна строка словаря LSA.
- Токенизация и exact-слой (tsvector 'russian' — тоже Snowball) стеммят согласованно.
- Метрики stats отражают активное поколение LSA и видят удерживаемые поколения.
- Автоматическая миграция данных через существующий механизм fingerprint-инвалидации, без ручных миграций БД.

**Non-Goals:**

- Не меняем категории токенов (техимена, гибриды), состав LSA-документа, параметры TF-IDF/SVD и механику поколений (retention current + previous остаётся).
- Не трогаем exact-слой (tsvector/pg_trgm) и лексический поиск.
- Не вводим лемматизацию/морфологические словари (pymorphy-класс) — избыточно для корпуса спек.
- Не меняем политику очистки поколений.

## Decisions

### D1. Snowball (Russian) из `github.com/kljensen/snowball` вместо списка окончаний

Чистый Go, нет транзитивных зависимостей, BSD-2. Алгоритм стандартный — тот же, что использует PostgreSQL в конфигурации 'russian' (exact-слой), слои поиска становятся согласованными. Детерминирован — инвариант «одинаковый корпус → одинаковая модель» сохраняется.

*Альтернативы:* точечный ремонт своего списка (дёшево, но суффиксный стемминг русского — бесконечная охота на баги: беглые гласные, чередования); порт Snowball вручную (дублирование готовой библиотеки); лемматизатор со словарём (точнее, но новая тяжелая зависимость и недетерминированность версии словаря).

### D2. Замена инкапсулирована в `stemRussian`, контракт токенизатора не меняется

`Tokenize` сохраняет порядок и категории: техимена → гибриды → русские слова. Вызов `stemRussian(lower)` заменяется на Snowball-стемминг; нормализация ё→е остаётся до стемминга. Функция-обёртка сохраняется как единая точка подмены (и для будущих bump'ов версии).

### D3. Рунные проверки длины

`utf8.RuneCountInString` вместо `len`: аббревиатуры — ≤ 4 рун (было: ≤ 4 байт ≈ 2 буквы), минимальная длина стема — 2 руны. Латиница и гибриды не затронуты (байт и руна там совпадают по счёту).

### D4. Стоп-словарь по стемам записей

Поверх существующей проверки `stopWords[stemmed] || stopWords[lower]` добавляется предвычисленное (при инициализации пакета) множество стемов записей стоп-словаря — падежные формы стоп-слов («которого», «которому») отфильтровываются без ручного перечисления форм.

### D5. `TokenizerVersion` 2 → 3 — миграция через fingerprint

Версия токенизатора входит в `CorpusFingerprint`, поэтому после обновления бинарника обученная модель перестаёт совпадать с корпусом по fingerprint. Безусловно (минуя порог `lsa_retrain_threshold`) переобучают только: отсутствие state, retry-маркер незавершённой попытки, смена `AlgorithmVersion` или параметров модели. Смена версии токенизатора идёт через fingerprint и при ненулевом пороге без изменений спек уходит в ветку Defer (delta=1 < порога) — переобучение форсирует оператор (см. Migration Plan). Удержание previous обеспечивает откат.

### D6. Метрики stats: активное поколение из sidecar-state, фолбэк — полный счёт

`systemsvc.ExecuteStats` после `config.Get()` читает путь sidecar-state (`config.SpecLSAStatePath()`, не путь бинарной модели) → `specfts.LoadLSAState` → `Generation` и передаёт его в `db.GetStats(ctx, lsaGeneration)`. При `lsaGeneration == ""` (state-файл отсутствует/повреждён/пуст) счётчики возвращаются без фильтра — ошибка чтения не заваливает stats. SQL: `COUNT(*) FILTER (WHERE generation = $1)` для vocab/embeddings; `spec_lsa_generations` = `COUNT(DISTINCT generation)` из `spec_vocab` (поколения согласованы между vocab и embeddings по конструкции публикации).

*Альтернатива:* вычислять «активное» поколение чисто в SQL (максимум строк) — ненадёжно: размер предыдущего поколения может превышать текущее. Хранить generation в БД-таблице состояния — дублирование sidecar-источника истины.

### D7. Совместимость JSON stats

`spec_vocab_terms`/`spec_embeddings` меняют семантику (активное поколение вместо суммы) — задокументировано как BREAKING для внешних скриптов мониторинга; новое поле `spec_lsa_generations`. `format_version` остаётся `1.0` (изменение полей, не формата envelope).

## Risks / Trade-offs

- [Snowball агрессивнее в отдельных случаях: непривычные стемы, часть прежних «хороших» совпадений изменит вес] → контроль: golden-тест на `testdata/lsacorpus` обновляется осознанно, аудит качества через `Tests/lsaaudit` (OOV-метрика должна уменьшиться).
- [Новое поведение минимальной длины/аббревиатур меняет состав словаря] → покрыто unit-тестами токенизатора; изменения в рамках того же bump'а версии.
- [До переобучения semantic-слой деградирован: запросы уже стеммятся Snowball (v3), а активный словарь в БД — прежние v2-стемы, русская лексика запроса уходит в OOV] → переобучать сразу после деплоя по процедуре Migration Plan (форсирование через нулевой порог или удаление state).
- [kljensen/snowball — внешняя зависимость] → без транзитивных зависимостей, стабильный API, при выпадении библиотеки замена локализована обёрткой из D2.
- [Мониторинг увидит «падение» spec_vocab_terms вдвое] → ожидаемый эффект, зафиксирован в proposal (BREAKING) и Notes спеки stats.

## Migration Plan

1. Деплой бинарника; schema БД не меняется.
2. Форсировать переобучение LSA: fingerprint отличается (tokenizer=3), но при `lsa_retrain_threshold > 0` прогон без изменений спек уйдёт в Defer (delta=1 < порога). Один из способов:
   - временно выставить `lsa_retrain_threshold = 0` в `codebase.toml` → выполнить `codebase update` → вернуть прежний порог; или
   - удалить файл модели и sidecar-state из каталога `models/` рядом с `codebase.toml` → следующий `codebase update` обучит безусловно (ветка «первый запуск» в `decideLSARetrain`).
3. Окно деградации: между деплоем и переобучением semantic-слой теряет русскую лексику (v3-стемы запросов против v2-словаря → OOV); переобучать сразу, не откладывая.
4. После обучения публикуется новое поколение vocab/embeddings, previous удерживается штатно (`DeleteSpecLSAGenerationsExcept`).
5. Откат: вернуть старый бинарник — fingerprint снова отличается, переобучение форсируется теми же способами; данные поколений обратно совместимы.

## Open Questions

- Нужен ли кэш стеммов (query-side `ProjectQuery` стеммит на лету) — на текущих объёмах (~2.3k документов, короткие запросы) избыточен; вернуться, если замеры `Tests/lsaktune` покажут заметную долю стемминга в профиле.
