# Delta: query/spec-search

## MODIFIED Requirements

### Requirement: Семантический слой — TF-IDF + LSA

Система SHALL строить семантический слой поиска через TF-IDF + LSA: токенизация с тремя категориями терминов (русские слова — нижний регистр, нормализация ё→е и стемминг по алгоритму Snowball (Russian), схлопывающий падежные и адъективные формы одного слова в один стем; технические идентификаторы — как есть, единым токеном; гибриды вида `758П`/`275-ФЗ` — как есть), словарь с фильтрацией minDF/maxDF, TF-IDF с log-нормализацией (учитывающей кратности терминов, включая удвоенный title) и smooth IDF, SVD-разложение (gonum) на все термины словаря. Токенизация MUST использовать рунные проверки длины: русские аббревиатуры из заглавных букв длиной до 4 символов не стеммятся и проходят как единый токен в нижнем регистре; стемы короче 2 символов отбрасываются. Стоп-слова MUST отфильтровываться как по исходной форме, так и по стему (стемы записей стоп-словаря предвычисляются тем же алгоритмом). LSA применяется на уровне capability (embed_level = 'spec'): каждый capability получает k-мерный вектор; k настраивается (`lsa_k`, default 512 — поднимает редкие термины в топ выдачи); requirement-уровень покрывается только лексическим слоем.

#### Scenario: Семантическая близость через ко-встречаемость

- **GIVEN** корпус спек, где «арест» и «блокировка» встречаются в одних документах
- **WHEN** выполняется поиск «блокировка счёта» семантическим слоем
- **THEN** capability про арест счёта попадает в секцию семантически близких с косинусной оценкой

#### Scenario: Технический идентификатор как единый токен

- **GIVEN** тексты спек со словами `CON_STP_MassAccrual` и обычной русской лексикой
- **WHEN** строится словарь
- **THEN** `CON_STP_MassAccrual` — один токен словаря (не разбит на части), русский текст — стеммированные токены

#### Scenario: Редкий термин требования находится семантически

- **GIVEN** термин встречается только в текстах требований нескольких capability и проходит minDF
- **WHEN** выполняется семантический поиск по этому термину
- **THEN** capability с этим термином в требованиях входят в топ-5 семантической выдачи (замер k-тюнинга: k=512 против k=128 поднимает позицию с #18 до #5)

#### Scenario: Падежные формы одного слова — один стем

- **GIVEN** тексты спек содержат формы «автоматический», «автоматическим», «автоматического», «автоматическому»
- **WHEN** строится словарь LSA
- **THEN** все формы отображаются в один стем «автоматическ»: словарь содержит одну строку с суммарной doc_freq, обособленных осколков («автоматическо», «автоматическу», «автоматическим») нет

#### Scenario: Запрос в непрямой форме находит документы

- **GIVEN** capability содержит требование с формой «автоматическим начислением», запрос выполняется в форме «автоматическое начисление»
- **WHEN** строится вектор запроса
- **THEN** стем «автоматическ» входит в словарь модели и совпадает со стемом документа — термин не попадает в OOV-диагностику

#### Scenario: Аббревиатура не искажается стеммингом

- **GIVEN** текст спек содержит аббревиатуру «США» (заглавные буквы, ≤ 4 символов)
- **WHEN** выполняется токенизация
- **THEN** аббревиатура попадает в словарь токеном «сша» целиком, без усечения до «сш»

#### Scenario: Падежная форма стоп-слова отфильтрована

- **GIVEN** текст спек содержит форму «которого» при наличии записи «который» в стоп-словаре
- **WHEN** выполняется токенизация
- **THEN** форма отфильтрована: её стем совпадает с предвычисленным стемом стоп-слова и не попадает в словарь LSA
