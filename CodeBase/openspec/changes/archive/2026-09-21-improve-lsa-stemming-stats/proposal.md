# Proposal: improve-lsa-stemming-stats

## Why

Самописный суффиксный стеммер `stemRussian` фрагментирует русскую лексику: формы одного слова попадают в словарь LSA отдельными терминами («автоматическ» df 393 / «автоматическо» df 91 / «автоматическу» df 17 / «автоматическим» df 64 — одна лексема «автоматическ-»), редкие осколки получают завышенный IDF и доминируют в векторе запроса, а падёжные формы запроса и документа не совпадают — semantic-слой теряет recall. Параллельно метрики `stats` считают `spec_vocab`/`spec_embeddings` без фильтра по generation, что удваивает числа при штатном удержании предыдущего поколения и вводит в заблуждение при мониторинге.

## What Changes

- Стемминг русских слов в токенизаторе LSA переводится с самописного списка окончаний на алгоритм Snowball (Russian) — библиотека `github.com/kljensen/snowball`; категории техимён и гибридов не меняются.
- `TokenizerVersion` 2 → 3: fingerprint корпуса меняется, накопленная модель становится неактуальной; переобучение форсируется оператором (нулевой `lsa_retrain_threshold` на один прогон или удаление state/модели — при ненулевом пороге и без изменений спек решение уйдёт в Defer), после чего мусорные стемы предыдущих поколений исчезают из активного словаря.
- Починка байтовых проверок длины в токенизаторе: фильтр аббревиатур (≤ 4 символов, сейчас — 4 байта = 2 кириллические буквы, «США» стеммилось в «сш») и минимальная длина стема (2 символа) переводятся на подсчёт рун.
- Стоп-словарь проверяется также по стемам своих записей (предвычисленных Snowball), чтобы отфильтровывать падёжные формы стоп-слов.
- Метрики `stats` становятся generation-осведомлёнными: `spec_vocab_terms`/`spec_embeddings` считаются по активному поколению LSA (из sidecar-файла state), при недоступности state — фолбэк на текущее полное число; добавляется метрика `spec_lsa_generations` (число удерживаемых поколений).
- **BREAKING** (для мониторинга/скриптов, читающих JSON stats): значения `spec_vocab_terms` и `spec_embeddings` меняют семантику — теперь это активное поколение, а не сумма всех поколений; новое поле `spec_lsa_generations`.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `query/spec-search`: требование «Семантический слой — TF-IDF + LSA» — стемминг русских слов выполняется алгоритмом Snowball (Russian) вместо самописного суффиксного списка; токенизация использует рунные проверки длины; scenarios покрывают слияние падёжных форм и обработку аббревиатур.
- `infrastructure/encoding-cli`: требование «Stats через systemsvc» — подсчёт `spec_vocab`/`spec_embeddings` фильтруется по активному поколению LSA с фолбэком; в статистике появляется число поколений LSA.

## Impact

- Код:
  - `internal/specfts/tokenizer.go` — замена `stemRussian` на Snowball, рунные длины, стоп-словарь по стемам.
  - `internal/specfts/lsa.go` — bump `TokenizerVersion` до 3.
  - `internal/specfts/vocab_tfidf.go`, `internal/specsvc/specsvc.go` — без изменений поведения, зависят от токенизатора.
  - `internal/store/db_stats.go`, `internal/systemsvc/runtime.go`, `cmd/stats.go` — generation-осведомлённые метрики, поле `spec_lsa_generations`.
- Зависимости: + `github.com/kljensen/snowball` (чистый Go, без транзитивных зависимостей, BSD-2).
- Данные: schema БД не меняется; переобучение LSA после деплоя форсируется оператором (`lsa_retrain_threshold = 0` на один `codebase update` или удаление файлов модели/state из `models/`) — процедура и окно деградации semantic-слоя до переобучения описаны в design.md (Migration Plan); удержание предыдущего поколения (current + previous) сохраняется.
- Тесты: обновляются ожидания стемминга в `internal/specfts/*_test.go`, golden-тест LSA на `testdata/lsacorpus`; добавляются интеграционные проверки метрик stats.
- Мониторинг: значения `spec_vocab_terms`/`spec_embeddings` в JSON stats уменьшатся примерно вдвое (перестанут суммировать поколения) — ожидаемое и целевое поведение.
