## Purpose

Пакетный запуск статического review по списку SQL-файлов: один вызов команды
обрабатывает много файлов, изолирует ошибки по каждому файлу и возвращает
агрегированный machine-readable результат.

## ADDED Requirements

### Requirement: Пакетный запуск review по списку файлов

CLI `review` SHALL поддерживать пакетный режим через флаг `--files <list-file>`
вместо позиционного аргумента `<sql-file-path>`. В пакетном режиме команда MUST
обрабатывать все файлы из списка в порядке их следования, применяя к каждому
файлу одни и те же `--rules`, `--min-severity` и `--dsinfo`. Одновременная
передача позиционного пути и `--files` MUST считаться ошибкой аргументов.

#### Scenario: Пакетный прогон списка

- **GIVEN** список `list.txt` из трёх проиндексированных SQL-файлов и запуск `review --files list.txt --json`
- **WHEN** команда выполняется
- **THEN** все три файла проверяются в порядке списка
- **AND** ответ содержит результаты по каждому файлу и суммарный `count`

#### Scenario: Конфликт режимов

- **GIVEN** запуск `review path/to/file.sql --files list.txt`
- **WHEN** команда разбирает аргументы
- **THEN** команда завершается ошибкой `invalid_arguments`
- **AND** ни один файл не проверяется

#### Scenario: Пустой список

- **GIVEN** файл списка существует, но не содержит ни одного пути
- **WHEN** выполняется `review --files list.txt`
- **THEN** команда завершается ошибкой `invalid_arguments`
- **AND** сообщение указывает, что список файлов пуст

### Requirement: Разбор списка и разрешение путей

Список файлов SHALL читаться как UTF-8, по одному пути на строку. Команда MUST
игнорировать пустые строки и строки, начинающиеся с `#`, обрезать окружающие
пробелы и парные кавычки, а также схлопывать повторяющиеся пути с сохранением
порядка первого вхождения. Относительные пути MUST разрешаться от текущей
рабочей директории процесса — так же, как позиционный аргумент `<sql-file-path>`.
Отсутствующий или нечитаемый файл списка MUST приводить к ошибке команды.

#### Scenario: Комментарии и пустые строки

- **GIVEN** список с пустыми строками, комментариями `# ...` и путями в кавычках
- **WHEN** выполняется пакетный review
- **THEN** комментарии и пустые строки не считаются файлами
- **AND** кавычки вокруг путей не попадают в путь

#### Scenario: Дубликаты путей

- **GIVEN** список, где один и тот же путь указан дважды
- **WHEN** выполняется пакетный review
- **THEN** этот файл проверяется один раз
- **AND** в результатах он присутствует в позиции первого вхождения

#### Scenario: Относительные пути

- **GIVEN** список содержит `fa-contracts/Consumer/.../File.sql`
- **WHEN** команда запущена из корня `root_path`
- **THEN** путь разрешается от текущей рабочей директории
- **AND** проверяется соответствующий проиндексированный файл

### Requirement: Изоляция ошибок и эквивалентность одиночному запуску

Ошибка обработки отдельного файла (файл не проиндексирован, отсутствует
`ds_product_id`, ошибка чтения, декодирования или парсинга) MUST NOT прерывать
обработку остальных файлов. Для каждого успешно обработанного файла набор
findings в пакетном режиме MUST совпадать с результатом одиночного вызова
`review <file>` при тех же `--rules`, `--min-severity` и `--dsinfo` и при
неизменном во время прогона состоянии индекса и dsinfo-профиля. Команда MUST
завершаться с ненулевым кодом возврата, если хотя бы один файл завершился
ошибкой.

#### Scenario: Непроиндексированный файл в середине списка

- **GIVEN** список из трёх файлов, где второй файл не проиндексирован
- **WHEN** выполняется пакетный review
- **THEN** первый и третий файлы проверяются
- **AND** для второго файла возвращается ошибка уровня файла
- **AND** exit code ненулевой

#### Scenario: Эквивалентность одиночному запуску

- **GIVEN** файл `A.sql` с известным набором findings
- **WHEN** он проверяется одиночным `review A.sql --rules truncTbl` и в составе пакетного списка с теми же флагами
- **THEN** набор findings (rule, severity, line, object) для `A.sql` совпадает в обоих режимах

### Requirement: Агрегированный JSON-ответ пакетного режима

В пакетном режиме с `--json` команда SHALL возвращать один JSON-конверт со
следующими полями: `success`, `format_version`, `command="review"`,
`mode="batch"`, `count` (суммарное число findings), `items` (плоский массив
findings; каждый finding содержит `file`), `summary` (агрегация `by_rule` и
`by_severity` по всем успешным файлам), `files` и `meta` (`rules`,
`min_severity`). Блок `files` MUST содержать `total`, `succeeded`, `failed` и
`results[]`. `total` MUST равняться числу уникальных файлов после разбора
списка (дубликаты схлопнуты), `succeeded` — числу успешно обработанных,
`failed` — числу файлов с ошибкой, при этом
`succeeded + failed = total`; `results[]` содержит по одному элементу на
уникальный файл в порядке первого вхождения. Каждый элемент `results[]` MUST
содержать `file`, `status` (`ok` или `error`), а для `ok` — `count` и
`summary`, для `error` — объект `error` с `code` и `message`. Поле `file` в
`results[]` MUST содержать нормализованный (`normalizePath`) путь в том виде,
в каком он передан в списке; `items[].file` MUST оставаться индексным путём,
как в одиночном режиме. Поле `success` MUST быть `true` только если `failed`
равно нулю; при наличии ошибок findings успешных файлов всё равно включаются в
`items`. Порядок `items` MUST соответствовать порядку файлов в списке, внутри
файла — порядку findings одиночного запуска.

#### Scenario: Успешный пакетный ответ

- **GIVEN** список из двух файлов без ошибок, суммарно три findings
- **WHEN** выполняется `review --files list.txt --json`
- **THEN** `mode` равно `batch`, `count` равно `3`
- **AND** `files.total` и `files.succeeded` равны `2`, `files.failed` равно `0`, `success` равно `true`
- **AND** `items` содержит три finding'а с корректным `file`

#### Scenario: Частичный успех

- **GIVEN** список из двух файлов, один из которых не проиндексирован
- **WHEN** выполняется `review --files list.txt --json`
- **THEN** `files.total` равно `2`, `files.succeeded` равно `1`, `files.failed` равно `1`, `success` равно `false`
- **AND** `items` содержит findings успешного файла
- **AND** `results[]` содержит элемент со `status="error"` и `error.code`

#### Scenario: Дедупликация списка уменьшает total

- **GIVEN** список, в котором один и тот же путь указан дважды
- **WHEN** выполняется `review --files list.txt --json`
- **THEN** `files.total` равно `1`
- **AND** `results[]` содержит один элемент для этого файла

### Requirement: Человекочитаемый вывод и прогресс пакетного режима

Без `--json` команда SHALL выводить результаты по файлам: заголовок с путём
файла, его findings и, для ошибок, сообщение об ошибке. Блок файла MUST
выводиться сразу после завершения обработки этого файла, не дожидаясь конца
пакета; в конце MUST выводиться общий итог с числом успешных файлов, ошибок и
суммарным числом findings. Прогресс обработки MUST отображаться в stderr с
указанием текущего файла и позиции `i/N`; в режиме `--json` stdout MUST
содержать только JSON-конверт.

#### Scenario: Итог пакетного прогона

- **GIVEN** пакетный прогон без `--json`
- **WHEN** обработка завершена
- **THEN** вывод содержит блоки по каждому файлу в порядке списка
- **AND** блок файла появляется сразу после его обработки, до завершения всего пакета
- **AND** в конце выводится общий итог с количеством успешных файлов, ошибок и findings

#### Scenario: JSON не загрязняется прогрессом

- **GIVEN** пакетный прогон с `--json`
- **WHEN** команда выполняется
- **THEN** stdout содержит только один валидный JSON-конверт
- **AND** прогресс не попадает в stdout

### Requirement: Совместимость одиночного режима и MCP

Одиночный режим `review <sql-file-path>` и MCP-инструмент
`codebase_review_sql` MUST сохранять текущее поведение и контракт ответа; поля
`mode` и `files` MUST появляться только в пакетном режиме.

#### Scenario: Одиночный запуск не изменился

- **GIVEN** запуск `review A.sql --json`
- **WHEN** команда выполняется
- **THEN** ответ содержит `count`, `items`, `summary` и `meta` как раньше
- **AND** поля `mode` и `files` отсутствуют

#### Scenario: MCP-инструмент без изменений

- **GIVEN** MCP-вызов `codebase_review_sql` с одним `file_path`
- **WHEN** инструмент выполняется
- **THEN** возвращается результат одиночного review без пакетных полей
