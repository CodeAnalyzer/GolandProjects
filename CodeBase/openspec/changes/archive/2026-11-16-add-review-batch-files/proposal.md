## Why

Сейчас `review` принимает ровно один SQL-файл, поэтому прогон по пачке файлов
(корпус FA, изменённые файлы в CI, подготовка тест-кейсов review-правил)
требует N отдельных запусков процесса. Каждый запуск заново читает конфиг,
подключается к PostgreSQL, проверяет схему и резолвит dsinfo/scope — при
холодном старте это десятки секунд, при горячем ~1 с на файл, плюс неудобная
агрегация результатов на стороне скрипта.

## What Changes

- Новый флаг CLI `review --files <list-file>`: пакетный режим по списку путей
  (один путь в строке) вместо позиционного `<sql-file-path>`.
- Пакетный прогон выполняется одним процессом и одним соединением с БД:
  конфиг, проверка схемы, `store.DB` и scope-инвариантные lookup'ы
  (список продуктов/веток, dsinfo-профиль) переиспользуются между файлами.
- JSON-ответ пакетного режима: единый конверт с суммарными `count`/`summary`,
  плоским `items[]` (каждый finding уже содержит `file`) и блоком `files`
  с результатом по каждому файлу (`ok`/`error`, счётчик, ошибка).
- Политика ошибок: ошибка отдельного файла (не проиндексирован, нет
  `ds_product_id`, ошибка чтения/парсинга) не прерывает пакет; она попадает в
  `files.results[]`, остальные файлы обрабатываются, exit code ненулевой при
  наличии ошибок.
- Человекочитаемый вывод: заголовок на файл + общий итог; прогресс в stderr
  показывает текущий файл и `i/N`.
- Список: пустые строки и `#`-комментарии игнорируются, дубликаты путей
  схлопываются с сохранением порядка, относительные пути резолвятся от CWD
  (как у позиционного аргумента).
- Поведение `review <sql-file-path>` и MCP-инструмента `codebase_review_sql`
  не меняется.

## Capabilities

### New Capabilities

- `review/batch-review`: пакетный запуск review-правил по списку файлов —
  разбор списка, переиспользование рантайма, агрегированный JSON-конверт,
  изоляция ошибок по файлам и прогресс.

## Impact

- `cmd/review.go` — второй режим аргументов (`--files`), сборка ответа, прогресс.
- `internal/reviewsvc/runtime.go` — API пакетного выполнения с общим `store.DB`.
- `internal/review/runner.go` — переиспользуемый рантайм/`Runner` для пачки,
  scope-инвариантные кэши, per-file сброс файловых кэшей.
- `cmd/review_test.go` (и, при необходимости, `internal/reviewsvc` тесты) —
  покрытие разбора списка, агрегации, ошибок по файлам.
- `Tests/TEST_CASES_REVIEW.md` (follow-up, создать при необходимости) —
  пакетные кейсы можно описать в будущем документе тест-кейсов review.
