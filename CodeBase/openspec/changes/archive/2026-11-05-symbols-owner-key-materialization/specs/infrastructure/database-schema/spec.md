# Delta: infrastructure/database-schema

## ADDED Requirements

### Requirement: Колонка owner_name в symbols и backfill-миграция

Таблица `symbols` SHALL содержать колонку `owner_name TEXT NOT NULL
DEFAULT ''`, добавляемую на существующих БД идемпотентно (`ALTER TABLE
... ADD COLUMN IF NOT EXISTS` после `CREATE TABLE`, по образцу
`files.is_generated`) и присутствующую в DDL свежих БД; изменение состава
DDL сопровождается bump маркера версии схемы (readonly-schema-policy).
Заполнение `owner_name` существующих строк SHALL выполняться однократной
именованной миграцией `symbols_owner_name_backfill_v1` с маркером в
таблице учёта миграций: UPDATE SHALL быть сужен на строки типов
`method`/`component` (для остальных типов DEFAULT `''` уже семантически
равен значению прежнего runtime-выражения), выполняться set-based
(`UPDATE ... FROM` к `pas_methods`/`pas_classes` и
`dfm_components`/`dfm_forms`, без per-row коррелированных подзапросов) и
давать для строк с резолвнутыми классом/формой значение, семантически
равное прежнему runtime-выражению ключа владельца, а для нерезолвнутых —
пустую строку (имя класса-ссылки не сохранено в индексе и backfill не
восстанавливает его). После применения маркера повторные прогоны
инициализации схемы SHALL NOT выполнять backfill. Новые записи
SHALL получать значение от индексатора при вставке.

#### Scenario: Существующая БД получает колонку и backfill

- **GIVEN** БД предыдущей версии схемы с символами `method`/`component`, чьи классы и формы резолвнуты
- **WHEN** выполняется первый `codebase update` после апгрейда
- **THEN** колонка `symbols.owner_name` добавлена и заполнена для method-строк именами резолвнутых классов, для component-строк — классами форм
- **AND** применение миграции зафиксировано маркером `symbols_owner_name_backfill_v1`

#### Scenario: Повторные прогоны — no-op

- **GIVEN** БД с применённым маркером backfill-миграции
- **WHEN** выполняется повторная инициализация схемы (в том числе после bump версии по другим причинам)
- **THEN** backfill-обновление не выполняется: вручную изменённый `owner_name` строки не возвращается миграцией к вычисленному значению

#### Scenario: Свежая БД — колонка без backfill

- **GIVEN** пустая БД
- **WHEN** выполняется `codebase init`
- **THEN** таблица `symbols` создана с колонкой `owner_name`
- **AND** backfill-миграция зафиксирована маркером без обновления строк (легаси-данных нет)

#### Scenario: Строки прочих типов не переписываются

- **GIVEN** БД предыдущей версии схемы с большим числом символов типов `procedure`, `table`, `class` и прочих, кроме `method`/`component`
- **WHEN** применяется миграция `symbols_owner_name_backfill_v1`
- **THEN** у символов прочих типов `owner_name` остаётся пустой строкой (значение DEFAULT)
- **AND** UPDATE затрагивает только строки типов `method`/`component`

#### Scenario: Легаси-методы с нерезолвнутым классом получают пустого владельца

- **GIVEN** БД предыдущей версии схемы с method-строками, чьи классы не резолвнуты (`class_id = 0` или класс отсутствует в `pas_classes`)
- **WHEN** применяется миграция `symbols_owner_name_backfill_v1`
- **THEN** у таких строк `owner_name` остаётся пустой строкой
- **AND** строки дедуплицируются по пустому ключу владельца до переиндексации их файлов
