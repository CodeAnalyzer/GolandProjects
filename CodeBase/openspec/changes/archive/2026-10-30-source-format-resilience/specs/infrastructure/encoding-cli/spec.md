## ADDED Requirements

### Requirement: Детекция UTF-16 по BOM и NUL-плотности

Система SHALL детектировать UTF-16 по маркеру порядка байт: BOM `FF FE` → UTF16LE, BOM `FE FF` → UTF16BE; BOM `EF BB BF` → UTF8 (BOM удаляется при декодировании). BOM-детект применяется раньше всех прочих эвристик (UTF-16LE-файл с кириллицей состоит из байтов `≤ 0x7F`, поэтому байтовая эвристика CP866/CP1251/UTF-8 и `utf8.Valid` его увидеть не могут). Для UTF-16 без BOM система SHALL применять эвристику NUL-плотности: файл, в котором NUL-байты (порождаемые ASCII-сегментами UTF-16) составляют значимую долю первых прочитанных байтов и сосредоточены почти целиком на позициях одной чётности, классифицируется как UTF-16 — LE при NUL на нечётных смещениях, BE при NUL на чётных. Единый BOM/NUL-детект SHALL быть доступен всем детекторам по содержимому: эвристике single-byte legacy-форматов, детектору XML-кодировки и детектору markdown-кодировки — файл в UTF-16 корректно классифицируется на любом из этих путей, включая повторное чтение с диска вне walk-воркера. Декодирование UTF16LE/UTF16BE в UTF-8 (с удалением BOM) SHALL поддерживаться теми же точками входа, что и однобайтовые кодировки (чтение файла и декодирование байтов); декодер кодировки UTF8 SHALL удалять ведущий BOM `EF BB BF` (U+FEFF не должен попадать в декодированный контент). Детектированная кодировка сохраняется как строковое значение `UTF16LE`/`UTF16BE` в `files.encoding`.

#### Scenario: UTF-16LE SQL с BOM

- **GIVEN** SQL-файл в UTF-16LE с BOM `FF FE` и русскими комментариями (фикстура `TC01_TechAddAgree_Status.sql`)
- **WHEN** выполняется детекция кодировки по содержимому
- **THEN** кодировка определена как UTF16LE
- **AND** файл декодирован в UTF-8: кириллические комментарии читаемы, NUL-байты отсутствуют

#### Scenario: UTF-16BE без BOM

- **GIVEN** файл в UTF-16BE без BOM, NUL-байты преобладают на чётных смещениях
- **WHEN** выполняется детекция по NUL-плотности
- **THEN** кодировка определена как UTF16BE, декодирование корректно

#### Scenario: UTF-16 без BOM по NUL-плотности

- **GIVEN** UTF-16LE-файл без BOM, в котором около половины байтов — NUL почти исключительно на нечётных позициях
- **WHEN** выполняется детекция по содержимому
- **THEN** файл классифицирован как UTF16LE и декодирован корректно

#### Scenario: Однобайтовый файл с редкими NUL не классифицируется как UTF-16

- **GIVEN** CP866 SQL-файл с единичными NUL-байтами, разбросанными по обеим чётностям
- **WHEN** выполняется детекция
- **THEN** NUL-эвристика не срабатывает, файл детектируется прежними правилами CP866/CP1251/UTF-8

#### Scenario: UTF-8 BOM

- **GIVEN** файл в UTF-8 с BOM `EF BB BF`
- **WHEN** выполняется детекция
- **THEN** кодировка определена как UTF8
- **AND** декодированный контент не начинается с U+FEFF (BOM удалён)

#### Scenario: Markdown в UTF-16 без BOM

- **GIVEN** markdown-файл в UTF-16LE без BOM, ASCII-доминирующий (NUL на нечётных смещениях)
- **WHEN** детектор markdown-кодировки проверяет содержимое
- **THEN** файл классифицирован как UTF16LE и декодирован корректно

#### Scenario: Значение кодировки в files.encoding

- **GIVEN** проиндексированный UTF-16LE-файл
- **WHEN** файл сохранён в индекс
- **THEN** в `files.encoding` сохранено `UTF16LE`

## MODIFIED Requirements

### Requirement: Кодировки по типам файлов

Система SHALL использовать карту расширений как **prior** (предположение по умолчанию и tie-breaker), а фактическую кодировку single-byte legacy-форматов — SQL (.sql), H (.h), TPR (.tpr), PAS (.pas), INC (.inc), JS (.js), SMF (.smf), DFM (.dfm), RPT (.rpt) — определять по содержимому через детекцию из требования «Детекция кодировок»: валидный/«почти валидный» UTF-8 с кириллицей → UTF-8; иначе счёт маркерных диапазонов CP866 vs CP1251 с победой по счёту и prior-ом при ничьей/слабом сигнале. Детектированная кодировка используется для декодирования и сохраняется в `files.encoding`. Форматы с собственной семантикой кодировки не меняются: XML — `DetectXMLEncoding`; MD (.md) — авто-детекция с приоритетом UTF-8 (openspec-артефакты финпродуктов хранятся в UTF-8, но встречаются legacy-файлы в CP1251): BOM/валидность UTF-8 → UTF-8, иначе CP1251 fallback; YAML (.yaml) — UTF-8; T01 (.t01) — CP866 (генерируемые препроцессором копии). Исключение для всех перечисленных правил: если BOM-детект или NUL-эвристика распознали UTF-16 (требование «Детекция UTF-16 по BOM и NUL-плотности»), кодировка этого файла — `UTF16LE`/`UTF16BE` независимо от формата и prior карты — UTF-16-байты невидимы для однобайтовых эвристик, а NUL не должен доходить до декодера формата.

#### Scenario: Чтение SQL в CP866

- **GIVEN** SQL-файл в кодировке CP866 (prior карты)
- **WHEN** выполняется индексация
- **THEN** детекция по содержимому подтверждает CP866, файл прочитан в CP866 и кириллические символы корректно декодированы

#### Scenario: SQL в CP1251 детектируется по содержимому

- **GIVEN** SQL-файл модуля fa-administrator в кодировке CP1251 (карта даёт prior CP866)
- **WHEN** выполняется индексация
- **THEN** детекция по содержимому определяет WIN1251 (артефакт-набор и заглавные А-Я перевешивают)
- **AND** кириллические комментарии и header-описания процедур декодированы без mojibake
- **AND** в `files.encoding` сохранено WIN1251

#### Scenario: PAS в CP866 детектируется по содержимому

- **GIVEN** PAS-файл, сохранённый в CP866 (отклонение от prior WIN1251)
- **WHEN** выполняется индексация
- **THEN** детекция по содержимому определяет CP866 (байты 0x80–0x9F перевешивают)
- **AND** кириллица декодирована корректно

#### Scenario: Чтение PAS в CP1251

- **GIVEN** PAS-файл в кодировке CP1251 (prior карты)
- **WHEN** выполняется индексация
- **THEN** детекция подтверждает CP1251, кириллические символы корректно декодированы

#### Scenario: UTF-8 исходник среди single-byte форматов

- **GIVEN** SQL-файл, сохранённый в UTF-8 с кириллическими комментариями
- **WHEN** выполняется индексация
- **THEN** валидность UTF-8 определяется раньше CP866/CP1251-эвристики, файл декодирован как UTF-8

#### Scenario: Файл с невалидным байтом получает детерминированный фолбэк

- **GIVEN** SQL-файл, содержащий байт 0x98, не мапящийся ни в UTF-8, ни в CP1251
- **WHEN** выполняется индексация
- **THEN** файл не является валидным UTF-8, детекция уходит в счёт диапазонов и возвращает кодировку по счёту/prior без ошибки декодирования

#### Scenario: YAML в UTF-16 распознаётся вопреки фиксированной кодировке

- **GIVEN** YAML-файл в UTF-16LE с BOM (правило формата — UTF-8)
- **WHEN** выполняется индексация
- **THEN** BOM-детект возвращает UTF16LE, файл декодирован из UTF-16, а не прочитан как UTF-8

#### Scenario: T01 в UTF-16 распознаётся вопреки фиксированной кодировке

- **GIVEN** препроцессированный `.t01`-файл, пересохранённый инструментом в UTF-16LE (правило формата — CP866)
- **WHEN** выполняется индексация
- **THEN** детект распознаёт UTF16LE до применения правила CP866
- **AND** в `files.encoding` сохранено UTF16LE

#### Scenario: T01-копия читается в CP866 без детекции

- **GIVEN** препроцессированный `.t01`-файл в CP866 без признаков UTF-16
- **WHEN** выполняется индексация
- **THEN** файл читается в CP866 по карте (генерируемая копия, детекция по содержимому не применяется)

#### Scenario: Markdown openspec-спеки в UTF-8

- **GIVEN** `spec.md` в UTF-8 (без BOM) с кириллическими требованиями
- **WHEN** выполняется индексация
- **THEN** файл корректно декодирован как UTF-8, кириллица требований сохранена без искажений

#### Scenario: Legacy-README в CP1251

- **GIVEN** markdown-файл, сохранённый в CP1251
- **WHEN** выполняется индексация
- **THEN** детектор распознаёт невалидный UTF-8 и читает файл как CP1251; кириллица декодирована корректно

#### Scenario: YAML-файл в UTF-8

- **GIVEN** YAML-файл в UTF-8
- **WHEN** выполняется индексация
- **THEN** файл прочитан в UTF-8 и кириллические символы корректно декодированы

#### Scenario: MD-файл в CP1251

- **GIVEN** MD-файл в CP1251
- **WHEN** выполняется индексация
- **THEN** детектор распознаёт невалидный UTF-8 и читает файл как CP1251; кириллица декодирована корректно

### Requirement: Детекция кодировки XML

Система SHALL определять кодировку XML-файлов через `DetectXMLEncoding(data)` по трём шагам: (0) UTF-16 детект выполняется раньше всего — BOM (`FF FE`/`FE FF`; декларация в таком файле не читается как ASCII, дальнейший разбор declaration не выполняется) и, при отсутствии BOM, NUL-эвристика по плотности и чётности (требование «Детекция UTF-16 по BOM и NUL-плотности»: ASCII-доминирующий UTF-16LE без BOM иначе виден как валидный UTF-8); BOM `EF BB BF` — UTF-8 с удалением BOM; (1) ищет `encoding="..."` в XML declaration (первые 200 байт) через `xmlEncodingRegexp`, поддерживает `windows-1251`/`cp1251`/`windows1251` → WIN1251, `cp866`/`ibm866` → CP866; при заявленном `utf-8`/`utf8` декларация SHALL проверяться на достоверность: если `utf8.Valid(data)` — UTF8, если нет — заявленной декларации не доверяют и кодировка определяется эвристикой по содержимому (маркерные диапазоны CP866/CP1251, как в требовании «Детекция кодировок»); (2) если declaration нет или encoding не указан — проверяет `utf8.Valid(data)`: валидный → UTF8, иначе WIN1251 (Diasoft heuristic для XML). Файл с ложной декларацией UTF-8 при однобайтовом содержимом SHALL декодироваться по фактической кодировке, а не ронять xml-парсер.

#### Scenario: XML с явной кодировкой

- **GIVEN** XML-файл с `<?xml version="1.0" encoding="windows-1251"?>`
- **WHEN** `DetectXMLEncoding` парсит declaration
- **THEN** кодировка определена как WIN1251

#### Scenario: XML с декларацией UTF-8 и валидным содержимым

- **GIVEN** XML-файл с `encoding="UTF-8"` и контентом, валидным как UTF-8
- **WHEN** `DetectXMLEncoding` проверяет декларацию
- **THEN** кодировка определена как UTF8

#### Scenario: XML с ложной декларацией UTF-8 (байты CP1251)

- **GIVEN** XML-файл с `<?xml version="1.0" encoding="UTF-8"?>`, но кириллицей в CP1251 (фикстура `API_GSOD_MassCreate.xml`)
- **WHEN** `DetectXMLEncoding` проверяет достоверность декларации
- **THEN** декларация отвергнута (контент не валиден как UTF-8), эвристика по содержимому возвращает WIN1251
- **AND** файл декодирован из CP1251 и успешно разобран xml-парсером
- **AND** русские описания (`ShortDescription` и т.п.) сохранены в индекс без mojibake

#### Scenario: XML в UTF-16 с BOM

- **GIVEN** XML-файл в UTF-16LE с BOM `FF FE`
- **WHEN** `DetectXMLEncoding` выполняет BOM-детект
- **THEN** кодировка определена как UTF16LE, содержимое декодировано до разбора declaration

#### Scenario: XML в UTF-16LE без BOM

- **GIVEN** XML-файл в UTF-16LE без BOM, ASCII-доминирующий (NUL почти целиком на нечётных смещениях)
- **WHEN** `DetectXMLEncoding` выполняет NUL-детект
- **THEN** файл классифицирован как UTF16LE (несмотря на валидность сырых байтов как UTF-8 из-за NUL), содержимое декодировано корректно

#### Scenario: XML без declaration, валидный UTF-8

- **GIVEN** XML-файл без `<?xml ...?>` declaration, контент валиден как UTF-8
- **WHEN** `DetectXMLEncoding` проверяет `utf8.Valid(data)`
- **THEN** кодировка определена как UTF8

#### Scenario: XML без declaration, невалидный UTF-8

- **GIVEN** XML-файл без declaration, контент не валиден как UTF-8
- **WHEN** `DetectXMLEncoding` откатывается к Diasoft heuristic
- **THEN** кодировка определена как WIN1251
