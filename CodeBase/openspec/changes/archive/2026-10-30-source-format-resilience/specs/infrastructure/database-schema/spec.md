## ADDED Requirements

### Requirement: Sanitization NUL в текстовых значениях

Система SHALL перед batch-вставкой гарантировать отсутствие байта `0x00` в текстовых значениях, попадающих в PostgreSQL (query_fragments, описания процедур/контрактов, symbols и прочие текстовые поля): PostgreSQL отвергает строки с NUL (`неверная последовательность байт для кодировки "UTF8": 0x00`), что роняет вставку всего файла. Найденные NUL-байты удаляются из значения; поведение — safety-net: NUL не должен доходить до драйвера БД даже при пропуске декодером экзотической кодировки. Проверка SHALL выполняться без выделения памяти для значений без NUL (быстрый предикат, замена — только при обнаружении).

#### Scenario: Значение с NUL вставляется без ошибки

- **GIVEN** распарсенный SQL-фрагмент, текст которого содержит байты `0x00` (например, недекодированный UTF-16 файл)
- **WHEN** выполняется batch-вставка
- **THEN** значение сохранено в PostgreSQL без NUL-байтов
- **AND** вставка и файл не падают с ошибкой кодировки

#### Scenario: Значение без NUL обрабатывается без накладных расходов

- **GIVEN** обычный текст без NUL-байтов
- **WHEN** выполняется batch-вставка
- **THEN** предикат NUL не вызывает копирования строки, содержимое сохраняется как есть

#### Scenario: Вставка множества строк с NUL в разных местах

- **GIVEN** batch из сотен строк, где NUL встречается в разных текстовых полях разных строк
- **WHEN** выполняется batch-вставка
- **THEN** все строки вставлены, ни одна не содержит NUL в БД
