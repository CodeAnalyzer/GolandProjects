## ADDED Requirements

### Requirement: Маскирование plpgsql-блоков перед анализом

Система SHALL маскировать содержимое dollar-quoted plpgsql-областей SQL-файла
до сегментации операторов и запуска правил review, чтобы правила, ориентированные
на MSSQL-диалект, не формировали findings по коду PostgreSQL.

Маскируемая область MUST охватывать:

- тело dollar-quoting `$$…$$` или `$tag$…$tag$` (парный закрывающий тег с тем же
  именем);
- объёмлющий оператор `CREATE [OR REPLACE] FUNCTION|PROCEDURE … AS $tag$…$tag$;`
  целиком — от строки `create` до строки закрывающего тега включительно: имя,
  список параметров, клаузу `language` и тело;
- анонимный блок `DO $tag$…$tag$;`.

Маскирование MUST заменять символы области пробелами, сохраняя переводы строк
(`\n` и `\r`): номера строк файла не смещаются, якоря findings указывают на
исходные строки. Открывающий dollar-quote MUST распознаваться только вне
одно-кавычных строковых литералов и комментариев; последовательность `$$`
внутри строкового литерала MUST NOT открывать или закрывать область. Серия из
трёх и более подряд идущих `$` MUST NOT открывать или закрывать область —
маркеры клиентских макросов вида `$$$NAME` не затрагиваются. Область оператора
`CREATE` MUST расширяться назад от открывающего тега до ближайшей строки
`create … function|procedure` только при отсутствии `;` между ними; в остальных
случаях маска ограничивается телом dollar-quote. Если парный закрывающий тег
не найден до конца файла, область MUST NOT маскироваться (fail-open);
остальные области файла маскируются независимо. Правила review MUST NOT
формировать findings по маскированным областям. Контент до маскирования,
используемый правилами для анализа директив препроцессора, MUST оставаться
немаскированным. Имя тега доллар-кавычки MUST быть пустым (`$$`) или
начинаться с буквы или подчёркивания — как unquoted-идентификатор PG:
последовательности вида `$1$` (форма позиционного параметра) область MUST NOT
открывать. Блочные комментарии PG вкладываются: `$$` на любой глубине
вложенности комментария MUST NOT открывать область.

#### Scenario: Чистый файл PL/pgSQL не даёт findings

- **GIVEN** SQL-файл целиком в PG-ветке: пять функций `create or replace function`
  с сигнатурами, содержащими дефолты `= ''` и `= null`, телами в `$$…$$`,
  динамическим `EXECUTE var_sql`, PG-хинтами в комментариях и PG-объектами
  (`master__sysprocesses`, `dblink_get_result`)
- **WHEN** выполняется review файла всеми правилами
- **THEN** findings отсутствуют
- **AND** код до изменения давал 27 findings, все ложные

#### Scenario: Смешанный файл — MSSQL-ветка разбирается, PG-ветка маскируется

- **GIVEN** файл с процедурой Diasoft в MSSQL-ветке до `#else` и
  `create or replace procedure … language plpgsql as $$…$$;` после
- **WHEN** выполняется review файла
- **THEN** findings MSSQL-ветки сохраняются без изменений (rule, object, line)
- **AND** findings из строк plpgsql-ветки отсутствуют

#### Scenario: Дефолт = null в PG-сигнатуре не даёт nullComparison

- **GIVEN** PG-сигнатура с параметром `var_param1 DSIDENTIFIER = null` внутри
  маскируемого create-оператора
- **WHEN** выполняется review с правилом nullComparison
- **THEN** finding по этой строке не формируется

#### Scenario: Доллары внутри строкового литерала не открывают маску

- **GIVEN** SQL-файл содержит строковый литерал с `$$$$$$$$` внутри и ниже —
  обычный MSSQL-код с нарушением, ловимым правилом
- **WHEN** выполняется review файла
- **THEN** нарушение ниже литерала даёт finding (маска не поглотила код за литералом)

#### Scenario: do-блок в доллар-кавычках маскируется

- **GIVEN** анонимный блок `do $$ … $$;` в SQL-файле
- **WHEN** выполняется review файла
- **THEN** содержимое блока не даёт findings

#### Scenario: create без dollar-quote не маскируется

- **GIVEN** обычная процедура `create procedure … as begin … end` без
  доллар-кавычек
- **WHEN** выполняется review файла
- **THEN** правила применяются к её телу как до изменения

#### Scenario: Маркеры $$$ не затрагиваются маской

- **GIVEN** SQL-файл содержит маркеры клиентских макросов `$$$NPPBEGIN$$$` и
  `$$$FAKE_…` в коде вне строковых литералов и комментариев
- **WHEN** выполняется review файла
- **THEN** маркеры не поглощаются маскированием
- **AND** findings файла совпадают с прогоном без маскирования

#### Scenario: Незакрытый dollar-quote не маскируется

- **GIVEN** SQL-файл содержит открывающий dollar-quote без парного
  закрывающего тега до конца файла
- **AND** ниже открывающего тега — нарушение, ловимое правилом
- **WHEN** выполняется review файла
- **THEN** нарушение обнаруживается (область не маскирована, fail-open)

#### Scenario: Вложенные блочные комментарии не открывают маску

- **GIVEN** SQL-файл содержит вложенный блочный комментарий, внутри которого
  после закрытия внутреннего уровня идёт `$$`, а ниже — настоящий dollar-quote
  и MSSQL-код с нарушением, ловимым правилом
- **WHEN** выполняется review файла
- **THEN** `$$` внутри комментария не открывает область (весь вложенный
  комментарий — комментарий, код за ним не поглощается)
- **AND** нарушение в MSSQL-коде обнаруживается

#### Scenario: Псевдо-тег с цифрой в первой позиции не открывает маску

- **GIVEN** SQL-код содержит пару последовательностей `$1$` и нарушение,
  ловимое правилом, между ними
- **WHEN** выполняется review файла
- **THEN** область между `$1$` не маскируется
- **AND** нарушение между ними обнаруживается

#### Scenario: Якоря findings не смещаются

- **GIVEN** смешанный файл: PG-область выше находки в MSSQL-ветке
- **WHEN** выполняется review файла
- **THEN** line каждого сохранённого finding указывает на ту же исходную строку,
  что и до изменения
