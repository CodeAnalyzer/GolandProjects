## Why

OpenCode запускает профильные MCP-процессы параллельно, а каждый процесс до начала stdio-handshake выполняет полный `InitSchemaCtx`. Конкурентные DDL-операции периодически конфликтуют в системном каталоге PostgreSQL с `pg_class_relname_nsp_index`, из-за чего MCP-клиент получает непрозрачную ошибку `-32000: Connection closed`.

## What Changes

- `InitSchemaCtx` становится безопасным для конкурентного вызова несколькими процессами: полный проход схемы сериализуется межпроцессной PostgreSQL advisory-блокировкой на выделенном соединении с поддержкой отмены через context.
- Добавляется явная проверка совместимости и готовности версии схемы без выполнения DDL.
- **BREAKING**: MCP startup перестаёт выполнять `InitSchemaCtx`: после подключения он проверяет схему и либо начинает stdio-обслуживание, либо завершается с диагностикой, предлагающей выполнить команду инициализации/миграции.
- Команды, ответственные за создание и обновление данных (`init` и `update`), сохраняют право применять схему; переходный механизм сериализации защищает также параллельные запуски других существующих вызывающих путей.
- Добавляются конкурентные интеграционные тесты и проверки поведения MCP при готовой, отсутствующей и несовместимой схеме.

### Modified Capabilities

- `infrastructure/database-schema`: задаётся гарантия конкурентно-безопасной инициализации и read-only проверки версии/готовности схемы.
- `mcp-server/mcp-transport-tools`: MCP startup проверяет схему без выполнения DDL и выдаёт понятную startup-диагностику при необходимости миграции.

## Impact

- Код: `internal/store/db_schema.go`, слой проверки схемы в `internal/store`, `internal/mcp/server.go`, CLI-точки применения схемы и интеграционные тесты.
- PostgreSQL: transaction-level advisory lock на выделенном соединении на время `InitSchemaCtx`; новые внешние зависимости не требуются.
- MCP: успешный протокол и набор инструментов не меняются; меняется только startup-поведение при неготовой схеме.
- Эксплуатация: перед MCP требуется выполненная инициализация/миграция схемы через предусмотренную CLI-команду; после обновления версии CodeBase существующую БД необходимо один раз актуализировать этой командой, чтобы записать текущий маркер совместимости.
