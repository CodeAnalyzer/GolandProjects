## MODIFIED Requirements

### Requirement: Идемпотентная инициализация схемы

Система SHALL создавать все таблицы и индексы БД при первом запуске `codebase init` через `InitSchemaCtx(ctx)`, идемпотентно (CREATE TABLE IF NOT EXISTS, CREATE INDEX IF NOT EXISTS). Система MUST сериализовать полный проход DDL между конкурентными процессами, подключёнными к одной БД, и удерживать межпроцессную блокировку на выделенной PostgreSQL-сессии до завершения прохода. Ожидание блокировки и все DDL-выражения SHALL выполняться с переданным `context.Context`, что позволяет отменить ожидание или длительную инициализацию. `InitSchema()` без контекста сохранён как deprecated-обёртка поверх `InitSchemaCtx(context.Background())` для обратной совместимости.

#### Scenario: Первый запуск

- **GIVEN** пустая БД PostgreSQL
- **WHEN** выполняется `codebase init`
- **THEN** все таблицы и индексы созданы без ошибок через `InitSchemaCtx(ctx)`
- **AND** после успешного прохода записан текущий маркер версии схемы

#### Scenario: Повторный запуск

- **GIVEN** БД с уже созданной схемой
- **WHEN** выполняется `codebase init` повторно
- **THEN** схема не пересоздаётся, существующие таблицы и индексы сохраняются
- **AND** текущий маркер версии схемы присутствует

#### Scenario: Конкурентная инициализация из нескольких процессов

- **GIVEN** несколько процессов подключены к одной БД PostgreSQL
- **WHEN** процессы одновременно вызывают `InitSchemaCtx`
- **THEN** один процесс выполняет DDL, а остальные ожидают освобождения общей блокировки
- **AND** после получения блокировки каждый ожидавший вызов успешно завершается
- **AND** ни один процесс не получает конфликт системного каталога PostgreSQL

#### Scenario: Отмена длительной инициализации

- **GIVEN** запущенный `codebase init` на крупном проекте
- **WHEN** пользователь нажимает Ctrl+C во время `InitSchemaCtx`
- **THEN** контекст отменён, ожидание блокировки или выполнение DDL прекращается без зависания
- **AND** удерживаемая процессом межпроцессная блокировка освобождается при завершении транзакции на выделенной сессии

## ADDED Requirements

### Requirement: Read-only проверка совместимости схемы

Система SHALL предоставлять read-only проверку совместимости схемы с текущей версией CodeBase. Проверка MUST подтверждать наличие таблицы учёта миграций и текущего маркера версии, не создавая, не изменяя и не удаляя объекты или данные БД. Отсутствующая схема, отсутствующий текущий маркер или ошибка чтения MUST возвращаться как различимая ошибка готовности с указанием необходимости выполнить предусмотренную CLI-команду инициализации или обновления.

#### Scenario: Совместимая схема

- **GIVEN** БД содержит таблицу учёта миграций и текущий маркер версии схемы
- **WHEN** выполняется read-only проверка совместимости
- **THEN** проверка успешно завершается
- **AND** состояние БД не изменяется

#### Scenario: Схема ещё не создана

- **GIVEN** целевая БД существует, но таблицы CodeBase отсутствуют
- **WHEN** выполняется read-only проверка совместимости
- **THEN** возвращается ошибка отсутствующей схемы
- **AND** диагностика указывает выполнить CLI-команду инициализации или обновления
- **AND** таблицы и индексы автоматически не создаются

#### Scenario: Требуется обновление схемы

- **GIVEN** таблица учёта миграций существует, но текущий маркер версии отсутствует
- **WHEN** выполняется read-only проверка совместимости
- **THEN** возвращается ошибка несовместимой версии схемы
- **AND** диагностика указывает выполнить CLI-команду обновления
- **AND** схема автоматически не изменяется
