## 3. Проверка корректности реализации

- Новая регулярка: `(?i)@\w+\s+\w+(?:\s*\([^)]*\))?\s*=\s*null\s*(?:out(?:put)?\s*)?,?\s*$`.
  Язык старой регулярки — подмножество новой: добавлены только строки с
  направлением `out`, `output` по-прежнему матчится через `out(?:put)?`.
- Хвостовой `--`-комментарий не мешает якорю `$`, т.к. `stripLineComments`
  (`review_helpers.go:1112`) вырезает его до проверки; это же подтверждает новый
  тест-кейс `-- passthrough`.
- `OUT`/`Out`/`out` в любом регистре — покрыты `(?i)`.
- `--min-severity` не мешает приёмочным командам: фильтр — `finding.Severity <=
  minSeverity` (`runner.go:240`), явный `--rules nullComparison` выводит
  severity 2 без флага (проверено).
- Единственный потребитель `nullParamDefaultRe` — `checkNullComparison`
  (`review_rules.go:4105`), других вызовов grep не находит.

## 6. Находки

### C1. Формулировка task 2.3 расходится с фактическим выполнением (мелкое)

Task 2.3 говорит «synthetic-файл в `Tests\Temp`», но `Tests\Temp` вне `root_path`
FA, и review требует индексированности (`file is not indexed`, воспроизведено),
поэтому файл временно размещался в `FA\fa-cards` и затем удалялся из дерева и
индекса. Это корректно описано в `acceptance-2.md`, но текст задачи не обновлён.

**Рекомендация.** Переформулировать 2.3: «synthetic-файл под `root_path` FA
(временное размещение и удаление — см. acceptance-2.md)». На результат не влияет.

### C2. Ссылка на номер строки в комментарии (info)

Комментарий ссылается на `review_helpers.go:2142`; номер со временем «уплывёт».
Приемлемо (та же практика в других комментариях), при желании заменить на имя
`isSQLKeywordNotType`.

### C3. `gofmt -l` показывает `cmd/root.go` (info, не связано с change)

Причина — CRLF-переводы строк всего файла (git предупреждает «LF will be
replaced by CRLF»), а не правка `buildNumber`. Pre-existing состояние, к change
не относится; Go-тулчейн собирает и тестирует без проблем.

### C4. `CodeBase.exe` изменён в рабочем дереве (info)

Бинарь пересобран и отдаёт build 1714 (проверено). Если бинарь не должен
попадать в коммит — исключить при коммите; если политика репозитория требует
обновлять его вместе с buildNumber (как в предыдущих change) — оставить.

### C5. Формулировка в acceptance-2 (info)

Фраза «0 из 823×83» читается неоднозначно; по сути — «пересечение списков файлов
по двум паттернам пусто». Косметика.
