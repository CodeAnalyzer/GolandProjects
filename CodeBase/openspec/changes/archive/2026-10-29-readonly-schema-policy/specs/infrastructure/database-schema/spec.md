## MODIFIED Requirements

### Requirement: Идемпотентная инициализация схемы

Система SHALL создавать все таблицы и индексы БД при первом запуске `codebase init` через `InitSchemaCtx(ctx)`, идемпотентно (CREATE TABLE IF NOT EXISTS, CREATE INDEX IF NOT EXISTS). При наличии в таблице учёта миграций актуального маркера версии схемы `InitSchemaCtx(ctx)` SHALL завершаться по fast-path — без выполнения DDL-выражений и без взятия межпроцессной блокировки. Перед выполнением DDL Система MUST сериализовать полный проход между конкурентными процессами, подключёнными к одной БД, и удерживать межпроцессную блокировку на выделенной PostgreSQL-сессии до завершения прохода; после взятия блокировки маркер версии SHALL проверяться повторно (double-check), и при актуальном маркере транзакция SHALL завершаться без выполнения DDL. Изменение состава DDL-выражений SHALL сопровождаться новым маркером версии схемы, чтобы изменения применялись на существующих БД. Ожидание блокировки и все DDL-выражения SHALL выполняться с переданным `context.Context`, что позволяет отменить ожидание или длительную инициализацию. `InitSchema()` без контекста сохранён как deprecated-обёртка поверх `InitSchemaCtx(context.Background())` для обратной совместимости.

#### Scenario: Первый запуск

- **GIVEN** пустая БД PostgreSQL
- **WHEN** выполняется `codebase init`
- **THEN** все таблицы и индексы созданы без ошибок через `InitSchemaCtx(ctx)`
- **AND** после успешного прохода записан текущий маркер версии схемы

#### Scenario: Повторный запуск

- **GIVEN** БД с уже созданной схемой и актуальным маркером версии
- **WHEN** выполняется `codebase init` повторно
- **THEN** инициализация завершается по fast-path без выполнения DDL-выражений и без взятия межпроцессной блокировки
- **AND** существующие таблицы, индексы и данные сохраняются, текущий маркер версии присутствует

#### Scenario: Конкурентная инициализация из нескольких процессов

- **GIVEN** несколько процессов подключены к одной БД PostgreSQL
- **WHEN** процессы одновременно вызывают `InitSchemaCtx` на неактуальной схеме
- **THEN** один процесс выполняет DDL, а остальные ожидают освобождения общей блокировки
- **AND** после получения блокировки каждый ожидавший вызов обнаруживает актуальный маркер (double-check) и завершается без повторного DDL
- **AND** ни один процесс не получает конфликт системного каталога PostgreSQL

#### Scenario: Отмена длительной инициализации

- **GIVEN** запущенный `codebase init` на крупном проекте
- **WHEN** пользователь нажимает Ctrl+C во время `InitSchemaCtx`
- **THEN** контекст отменён, ожидание блокировки или выполнение DDL прекращается без зависания
- **AND** удерживаемая процессом межпроцессная блокировка освобождается при завершении транзакции на выделенной сессии

#### Scenario: Актуальная схема не блокируется активным чтением

- **GIVEN** БД с актуальным маркером версии и открытая транзакция, удерживающая AccessShare-блокировку на таблице `files` (обычный выполняющийся SELECT)
- **WHEN** другой процесс вызывает `InitSchemaCtx` на той же БД
- **THEN** вызов завершается немедленно, не ожидая завершения читающей транзакции
- **AND** конфликтов блокировок AccessShare ↔ AccessExclusive не возникает

### Requirement: Признак is_generated в схеме файлов

Таблица `files` SHALL содержать колонку `is_generated BOOLEAN NOT NULL DEFAULT FALSE`. Миграция добавления колонки MUST быть идемпотентной (`ADD COLUMN IF NOT EXISTS`). Backfill существующих записей, соответствующих конвенциям генерируемых копий (сегмент пути `UPLOAD` без учёта регистра, расширение `t01`), SHALL выполняться однократно как именованная миграция с маркером в таблице учёта миграций: после применения маркера повторные прогоны инициализации схемы SHALL NOT выполнять backfill-обновление и сканирование таблицы `files`. Новые записи SHALL получать признак от индексатора при вставке.

#### Scenario: Новая инициализация

- **GIVEN** пустая база данных
- **WHEN** выполняется `codebase init` и создание схемы
- **THEN** таблица `files` создана с колонкой `is_generated`, новые записи получают признак от индексатора

#### Scenario: Существующая база после update без переиндексации

- **GIVEN** база данных с ранее проиндексированными копиями `*/UPLOAD/*.sql` и `*.t01`, у которых `is_generated` ещё не заполнен
- **WHEN** выполняется первый прогон инициализации схемы с именованной backfill-миграцией (в том числе при `codebase update`)
- **THEN** записи копий помечены `is_generated = true`, записи канонических исходников остались `false`
- **AND** применение миграции зафиксировано маркером в таблице учёта миграций

#### Scenario: Повторные прогоны инициализации без переиндексации

- **GIVEN** база данных с применённым маркером backfill-миграции
- **WHEN** выполняется повторная инициализация схемы (в том числе после bump версии по другим причинам)
- **THEN** backfill-обновление не выполняется, таблица `files` не сканируется
- **AND** результат пометки копий не меняется

## ADDED Requirements

### Requirement: Read-only команды не выполняют DDL

Все команды, кроме `init` и `update`, SHALL проверять совместимость схемы read-only проверкой версии и SHALL NOT создавать или изменять объекты схемы БД. Если таблица учёта миграций или актуальный маркер версии отсутствуют, команда SHALL завершаться различимой ошибкой готовности схемы (схема не создана / требуется обновление схемы) с диагностикой, указывающей выполнить `codebase init` или `codebase update`; молчаливая попытка миграции в read-only командах SHALL быть исключена. На актуальной схеме параллельные read-only команды SHALL NOT конкурировать за DDL-блокировки схемы.

#### Scenario: Запрос на актуальной схеме

- **GIVEN** БД с актуальным маркером версии схемы
- **WHEN** выполняется `codebase query procedure --name <имя>`
- **THEN** запрос выполнен без выполнения DDL-выражений
- **AND** DDL-блокировки схемы (ACCESS EXCLUSIVE) не запрашивались

#### Scenario: Пустая БД

- **GIVEN** целевая БД существует, но таблицы CodeBase отсутствуют
- **WHEN** выполняется read-only команда (например, `query` или `stats`)
- **THEN** возвращена различимая ошибка «схема не создана»
- **AND** диагностика указывает выполнить `codebase init`
- **AND** таблицы и индексы автоматически не создаются

#### Scenario: Устаревшая схема

- **GIVEN** таблица учёта миграций существует, но актуальный маркер версии отсутствует
- **WHEN** выполняется read-only команда (например, `query` или `health`)
- **THEN** возвращена различимая ошибка «требуется обновление схемы»
- **AND** диагностика указывает выполнить `codebase update`
- **AND** схема автоматически не изменяется

#### Scenario: Параллельные read-only команды

- **GIVEN** БД с актуальным маркером версии схемы
- **WHEN** две read-only команды выполняются одновременно (например, `query procedure` и `query callers`)
- **THEN** обе команды завершаются успешно
- **AND** взаимных блокировок AccessShare ↔ AccessExclusive и ошибок `deadlock detected` не возникает

#### Scenario: Команды анализаторов на пустой БД

- **GIVEN** целевая БД существует, но схема CodeBase не создана
- **WHEN** выполняется команда `rti`, `trc` или `dsinfo`
- **THEN** возвращена та же различимая ошибка готовности схемы с диагностикой
- **AND** низкоуровневая ошибка вида «relation does not exist» не поднимается наружу
