## Why

Семантический слой поиска спек (`layer=semantic`) возвращает шум и пропускает релевантные результаты: запрос «Заметка по клиенту» не находит capability `legal` (fa-generalledger), вместо неё выдаёт нерелевантные capability другого продукта (fa-reports, cosine 0.43–0.51), а релевантная находится только exact-слоем. Причины: (1) LSA-документ capability состоит только из title+purpose+notes — термины из требований и сценариев («заметка») не попадают в вектор; (2) порог косинуса 0.01 фиктивен — отсева по релевантности нет; (3) политика переобучения считает только capability за прогон — правки текста требований и удаления не переобучают модель, порог не накапливается между прогонами, а задать «переобучать всегда» конфигом невозможно (0 затирается дефолтом 50).

## What Changes

- Состав LSA-документа capability расширяется: title (с удвоенным весом) + purpose + notes + имена и тексты требований + имена и тексты сценариев. Уровень эмбеддинга остаётся `embed_level = 'spec'`.
- Политика переобучения заменяется на fingerprint-инвалидацию: детерминированный хеш корпуса (тексты всех capability с требованиями и сценариями) и параметров модели (minDF, maxDF, k, версия токенизатора, версия состава документа). Модель переобучается при отличии fingerprint; кумулятивный порог изменений (включая удаления) — опциональная амортизация, дефолт 100 по замеру стоимости SVD (~97 с на корпусе 2322 capability); явный 0 = «переобучать при любом изменении».
- Фильтрация semantic-секций: настраиваемый абсолютный порог косинуса (`lsa_min_cosine`, default 0.15) и относительный cutoff (`lsa_relative_cutoff` × maxRank), применяемые до `limit`; валидация диапазонов параметров.
- Размерность LSA повышена: k=128 → k=512 (настраивается). Замер k-тюнинга на боевом корпусе: редкий термин «заметка» поднимается с #18 до #5, «блокировка счёта» → card-block с #5 до #1; стоимость SVD не меняется (полное разложение считается независимо от k).
- Попутно исправлен давний баг SVD-обрезки: матрица Vᵀ обрезалась до min(nDocs, nTerms) колонок — при nTerms > nDocs термины с алфавитным индексом ≥ nDocs выпадали из проекции запроса (семантический слой на боевом корпусе фактически не работал). Введена `algorithm_version` в fingerprint — смена алгоритма переобучает модель безусловно.
- Диагностика пустой semantic-секции: метаполе с числом отсеянных результатов и причиной; hint, когда термины запроса вне словаря (OOV) — с отсылкой к exact-слою.
- Нормализация ё→е в токенизаторе LSA (сливает «счёт»/«счет» в один стем) с повышением версии токенизатора.
- Аудит minDF на реальном корпусе (df редких терминов, размер словаря при minDF 1/2) — значение по данным; benchmark-фикстура: golden-тест на синтетическом корпусе + ручной чек-лист контрольных запросов.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `query/spec-search`:
  - MODIFIED «Обучение и пересчёт LSA-модели» — fingerprint-инвалидация вместо счётчика за прогон; кумулятивный порог (default 0), идемпотентные прогоны, удаления и смена параметров как триггеры;
  - ADDED «Состав LSA-документа» — фиксирует состав документа capability (ранее не был специфицирован);
  - MODIFIED «Раздельные секции результата» — метаданные пустой semantic-секции (число отсеянных, порог) и hint при OOV-терминах запроса.

## Impact

- Код: `internal/indexer/indexer_postprocess_spec_lsa.go` (переобучение по fingerprint, агрегированный текст), `internal/store/db_lsa.go` (загрузка корпуса с requirements/scenarios, детерминированная агрегация), `internal/specfts/tokenizer.go` (ё→е, версии токенизатора/состава), `internal/specfts/vocab_tfidf.go` (без изменения логики; версии), `internal/specfts/lsa.go` (поля модели: fingerprint), `internal/specsvc/specsvc.go` (filterSemanticHits: абсолютный порог + relative cutoff до limit, OOV-диагностика), `internal/config/config.go` (`LSAMinCosine`, `LSARelativeCutoff`, семантика `LSARetrainThreshold`, валидация).
- Новые артефакты: sidecar-файл состояния LSA (`spec_lsa_state.json` рядом с моделью: fingerprint, pending-счётчик, параметры обучения).
- API: ответ MCP `codebase_query_spec_search` / CLI `query spec search` получает опциональные мета-поля semantic-секции — обратно совместимо.
- Модель: первый прогон после внедрения переобучит модель (состав документа и версия токенизатора изменились) — миграция не требуется, ручная инвалидация не нужна.
- Совместимость: exact-слой и `embed_level = 'spec'` не меняются; раздельность секций сохраняется.
