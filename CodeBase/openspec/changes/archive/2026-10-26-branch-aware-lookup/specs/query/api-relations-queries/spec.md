# Дельта: api-relations-queries — приоритет ветки

## ADDED Requirements

### Requirement: Приоритет релизной ветки в API-запросах

При нескольких копиях API-сущности (контракт, таблица, параметр, индекс)
в разных ветках система SHALL применять тот же детерминированный приоритет,
что и в entity queries (`not_generated` → default-ветка → больший id;
совпадение запрошенной ветки появится вместе с профилем `dsinfo-integration`),
и включать `branch_used` (нормализованный `branch_key`) в результаты поиска
контрактов, их таблиц/параметров, реализаций, публикаторов и потребителей.
Ключ дедупликации контракта SHALL включать вид контракта, чтобы
одноимённые контракты разных видов не схлопывались. Запросы к графу связей
SHALL возвращать рёбра в пределах фактически выбранной ветки сущности и
сообщать `branch_used`; дублирующие копии сущности из других веток не SHALL
порождать дублирующие рёбра в одном ответе.

#### Scenario: Контракт в develop и релизной линии

- **GIVEN** контракт `ExecContractService`, проиндексированный в develop и в `fa-contracts-11-01-7`
- **WHEN** выполняется поиск контракта по имени
- **THEN** возвращена копия из default-ветки с `branch_used`

#### Scenario: Граф без дублирующих рёбер

- **GIVEN** процедура, реализующая контракт, и копии обеих сущностей в двух ветках
- **WHEN** выполняется запрос реализаций контракта
- **THEN** реализации перечислены для выбранной копии контракта без дублей из второй ветки
