# Дельта: relations-postprocessing — scope ветки источника

## ADDED Requirements

### Requirement: Резолв имён в scope ветки источника

Пост-обработка графа (вызовы процедур из query fragments и JS, PAS↔DFM
связи, API-макросы, фрагменты, резолв spec_code_mentions) SHALL резолвить
имена в scope файла-источника. Множество кандидатов SHALL быть ограничено
тремя ярусами: (1) копии в ветке источника; (2) копии в default-ветке того
же продукта; (3) копии в других продуктах (приоритет их default-веток,
затем больший id). Копии остальных веток того же продукта SHALL
исключаться из множества кандидатов: ребро в чужую релизную ветку того же
продукта не SHALL создаваться, а имя, не найденное среди кандидатов,
остаётся неразрешённым (pending/NULL). Внутри яруса (и между копиями
одного имени) приоритет SHALL определяться осями `not_generated`,
совпадения ветки источника, совпадения продукта, default-ветки и большего
id — в этом порядке. Для файла-источника без ветки (не-git файлы) scope
SHALL вырождаться в default-ветку продукта (если продукт известен) и
другие продукты. Существующая batch-механика резолва (одним запросом на
пачку имён, без N+1) SHALL сохраняться: scope передаётся в batch-запрос
группами по `(product, branch)` источников.

#### Scenario: Вызов процедуры в той же ветке

- **GIVEN** query fragment в ветке `fa-contracts-11-01-7`, вызывающий `MyProc`, и `MyProc` в develop и в `fa-contracts-11-01-7` с разными id
- **WHEN** выполняется пост-обработка вызовов
- **THEN** relation `calls_procedure` указывает на копию `MyProc` из `fa-contracts-11-01-7`

#### Scenario: Имя существует только в чужой ветке того же продукта

- **GIVEN** fragment в develop, вызывающий `OnlyInSP`, которая существует только в `fa-contracts-11-01-7`
- **WHEN** выполняется пост-обработка
- **THEN** relation не создаётся, ссылка остаётся неразрешённой (копии других веток того же продукта исключены из кандидатов)

#### Scenario: Общая утилита другого продукта

- **GIVEN** fragment в fa-contracts (develop), вызывающий `UTIL_X`, которая существует только в fa-gaap (develop)
- **WHEN** выполняется пост-обработка
- **THEN** relation `calls_procedure` создаётся на копию `UTIL_X` из fa-gaap (третий ярус кандидатов)

#### Scenario: Spec-упоминание резолвится в ветку спеки

- **GIVEN** спека в SP-worktree продукта fa-contracts упоминает процедуру `MyProc`, чьи копии есть в develop и в SP-линии
- **WHEN** выполняется пост-обработка spec_code_mentions
- **THEN** упоминание резолвится в копию из SP-линии (scope файла спеки)

#### Scenario: Batch-резолв с разными scope

- **GIVEN** pending-вызовы из файлов двух веток одного продукта
- **WHEN** выполняется `postProcessSQLProcedureCallRelations`
- **THEN** имена резолвятся batch-запросами, сгруппированными по scope источников, без построчных SELECT
