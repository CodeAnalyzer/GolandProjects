## MODIFIED Requirements

### Requirement: Гибридный поиск exact + semantic

Поиск `desc-search` SHALL выполнять запрос в двух слоях: лексическом
(FTS-вектор + trgm) и семантическом (LSA desc-модели), и объединять выдачу.
Семантические хиты SHALL находиться по перефразировкам (термины, отсутствующие
в описании дословно). Каждый хит SHALL помечаться источником (`exact` или
`semantic`) со своим рангом; для semantic-хитов SHALL применяться фильтр
минимального cosine и относительный cutoff от максимума. Semantic-слой MUST
применять гейт лексического покрытия запроса: если доля распознанных
лексических слов ниже `lsa_min_query_coverage`, semantic-хиты MUST NOT
возвращаться, а exact-слой продолжает работать. Покрытие SHALL считаться по
«сырым» word-токенам запроса (последовательности букв длиной не менее двух):
распознанным считается токен, для которого токенизатор построил токен, либо
слово из стоп-словаря; распознанные токенизатором стемы, отсутствующие в
словаре LSA из-за minDF/maxDF, считаются распознанными. Если запрос не содержит
word-токенов, покрытие равно 0. При отсутствии обученной desc-модели поиск SHALL
возвращать только exact-хиты без ошибки. Фильтр по kind и правило «контракт
вытесняет процедуру» SHALL действовать на объединённую выдачу.

> Примечание: semantic-слой возвращает ближайшие по латентной близости
> документы только для запросов с достаточным лексическим покрытием. Частично
> известный запрос, в котором доля нераспознанных слов ниже порога, подавляется
> гейтом; пустой результат возможен и для запроса, все слова которого
> нераспознаны. Exact-слой при этом продолжает работать.

#### Scenario: Семантический хит по перефразировке

- **GIVEN** обученная desc-модель и процедура, чьё описание описывает
  «возврат сумм из банка-партнёра»
- **WHEN** выполняется `desc-search --text "как вернуть деньги с банковского счёта партнёра"`
- **THEN** процедура найдена как semantic-хит, помеченная источником `semantic`

#### Scenario: Fallback без модели

- **GIVEN** desc-модель не обучена (корпус меньше минимума или первый запуск)
- **WHEN** выполняется `desc-search --text "<запрос>"`
- **THEN** возвращены только exact-хиты без ошибки

#### Scenario: Дедуп на объединённой выдаче

- **GIVEN** процедура, реализующая контракт с непустым описанием, найдена
  в обоих слоях
- **WHEN** формируется выдача
- **THEN** пара представлена одной записью контракта, дублирующие записи
  процедуры отсутствуют

#### Scenario: Смешанный запрос с нераспознанными словами

- **GIVEN** `lsa_min_query_coverage = 0.6` и запрос
  `"asdkjhasd несуществующий запрос zzz"`, где распознаны 2 слова из 4
  (покрытие 0.5)
- **WHEN** выполняется `desc-search --text "<запрос>"`
- **THEN** ответ успешен, semantic-хиты отсутствуют
- **AND** exact-слой продолжает работать и возвращает свои совпадения

#### Scenario: Порог покрытия отключён

- **GIVEN** `lsa_min_query_coverage = 0` и тот же смешанный запрос
- **WHEN** выполняется `desc-search --text "<запрос>"`
- **THEN** гейт покрытия не применяется, semantic-хиты возвращаются по
  обычным фильтрам cosine и относительного cutoff

#### Scenario: Стоп-слова не снижают покрытие

- **GIVEN** запрос `"расчёт для платежа"`
- **WHEN** вычисляется лексическое покрытие
- **THEN** предлог «для» считается распознанным стоп-словом, покрытие равно
  3/3, гейт не срабатывает

## ADDED Requirements

### Requirement: Диагностика semantic-слоя desc-search

Ответ `desc-search` SHALL содержать необязательный объект `semantic_meta`, если
semantic-слой не вернул ни одного хита или в запросе есть термины вне словаря
LSA. Объект SHALL содержать причину (`threshold` | `oov` | `query_coverage`),
долю лексического покрытия и применимый порог покрытия для причины
`query_coverage`, число отсеянных результатов и порог cosine для причины
`threshold`, список терминов вне словаря и подсказку для причины `oov`. Для
причины `query_coverage` число отсеянных результатов MUST NOT заполняться —
гейт применяется до скоринга. При непустом semantic-слое без терминов вне
словаря `semantic_meta` MUST отсутствовать. CLI SHALL отдавать объект в
`meta.semantic_meta`, сохраняя `items` и `meta.has_more`; MCP-инструмент
`codebase_query_desc_search` SHALL возвращать объект
`{items, has_more, semantic_meta}` вместо массива.

#### Scenario: Гейт покрытия с диагностикой

- **GIVEN** `lsa_min_query_coverage = 0.6` и запрос
  `"asdkjhasd несуществующий запрос zzz"`, где распознаны 2 слова из 4
  (покрытие 0.5)
- **WHEN** выполняется `desc-search --text "<запрос>"`
- **THEN** `semantic_meta` содержит причину `query_coverage`, покрытие 0.5,
  порог покрытия 0.6, нераспознанные слова `asdkjhasd`, `zzz` и подсказку
  воспользоваться exact-слоем
- **AND** число отсеянных результатов не заполняется

#### Scenario: Пустой semantic-слой по порогу

- **GIVEN** обученная модель и все semantic-кандидаты ниже абсолютного порога
  cosine
- **WHEN** выполняется `desc-search --text "<запрос>"`
- **THEN** `semantic_meta` содержит причину `threshold`, число отсеянных
  результатов и применённый порог cosine

#### Scenario: Термины вне словаря LSA

- **GIVEN** обученная модель и запрос, часть стемов которого отсутствует в
  словаре LSA
- **WHEN** semantic-слой не вернул хитов
- **THEN** `semantic_meta` содержит причину `oov`, список OOV-стемов и
  подсказку воспользоваться exact-слоем

#### Scenario: Semantic-хиты прошли фильтр

- **GIVEN** semantic-слой вернул хотя бы один хит и в запросе нет терминов вне
  словаря LSA
- **WHEN** выполняется `desc-search --text "<запрос>"`
- **THEN** `semantic_meta` отсутствует

#### Scenario: MCP-ответ desc-search

- **GIVEN** MCP-клиент вызывает `codebase_query_desc_search`
- **WHEN** поиск завершён успешно
- **THEN** ответ является объектом с полями `items`, `has_more` и, при
  необходимости, `semantic_meta`
- **AND** ответ не является массивом (изменение формы контракта)
