## MODIFIED Requirements

### Requirement: Раздельные секции результата

Система SHALL выдавать результат поиска двумя раздельными секциями — «точные
совпадения» (лексический слой, ранжирование ts_rank + trgm similarity) и
«семантически близкие» (LSA, косинусная оценка) — без слияния ранжирований;
документы, найденные обоими слоями, показываются в обеих секциях. Каждый
результат содержит продукт, slug/имя, уровень сущности, границы строк и
текст-фрагмент. Секция «семантически близкие» MUST фильтроваться настраиваемым
абсолютным порогом косинуса и относительным cutoff (доля от максимального
косинуса секции), применяемыми до ограничения лимита. Semantic-слой MUST
применять гейт лексического покрытия запроса: покрытие SHALL считаться по
«сырым» word-токенам запроса (последовательности букв длиной не менее двух),
распознанным считается токен, для которого токенизатор построил токен, либо
слово из стоп-словаря; распознанные токенизатором стемы, отсутствующие в
словаре LSA из-за minDF/maxDF, считаются распознанными; если запрос не содержит
word-токенов, покрытие равно 0. Если покрытие ниже `lsa_min_query_coverage`,
секция «семантически близкие» MUST быть пуста, exact-секция не затрагивается, а
диагностические метаданные MUST содержать причину `query_coverage`, долю
покрытия, применимый порог покрытия и список нераспознанных слов. Для причины
`query_coverage` число отсеянных результатов MUST NOT заполняться — гейт
применяется до скоринга кандидатов. Если секция
пуста после фильтрации или термины запроса отсутствуют в словаре LSA, ответ
MUST содержать диагностические метаданные: причину пустоты, число отсеянных
результатов и применимый порог (cosine — для причин фильтрации по рангу, порог
покрытия — для причины `query_coverage`); при терминах запроса вне словаря —
подсказку воспользоваться точным слоем. При недоступной модели режим `both` MUST
вернуть exact-секцию и диагностику недоступности semantic-слоя, а режим
`semantic` MUST завершиться явной ошибкой. Ошибки БД и повреждение модели MUST
возвращаться вызывающей стороне и не маскироваться как пустая выдача.

#### Scenario: Двухсекционный ответ

- **GIVEN** обученная модель и спеки, где часть совпадений точные, часть — только семантические
- **WHEN** выполняется `codebase query spec search --query "ограничение расходных операций"`
- **THEN** ответ содержит секцию точных совпадений (с ts_rank) и секцию семантически близких (с cosine score), перекрывающиеся документы видны в обеих

#### Scenario: Модель не обучена

- **GIVEN** индекс спек, но LSA-модель ещё не построена
- **WHEN** выполняется поиск со слоем `both`
- **THEN** возвращается exact-секция и диагностические метаданные с причиной недоступности semantic-слоя

#### Scenario: Модель не обучена в режиме semantic

- **GIVEN** индекс спек, но LSA-модель ещё не построена
- **WHEN** выполняется поиск со слоем `semantic`
- **THEN** возвращается явная ошибка недоступности модели, а не успешная пустая секция

#### Scenario: Ошибка semantic-запроса к БД

- **GIVEN** модель доступна, но чтение embeddings из БД завершается ошибкой
- **WHEN** выполняется поиск со слоем `semantic` или `both`
- **THEN** ошибка возвращается вызывающей стороне и не подавляется

#### Scenario: Отсечение по порогам до лимита

- **GIVEN** обученная модель и semantic-кандидаты с косинусами 0.8 (максимум), 0.5, 0.3 при относительном cutoff 0.5 и лимите 10
- **WHEN** выполняется семантический поиск
- **THEN** кандидат 0.3 (ниже cutoff 0.4) отсечён до применения лимита, в секции остаются кандидаты 0.8 и 0.5

#### Scenario: Пустая секция с диагностикой

- **GIVEN** обученная модель и semantic-кандидаты, все ниже абсолютного порога
- **WHEN** выполняется семантический поиск
- **THEN** секция семантически близких пуста, ответ содержит метаданные: число отсеянных результатов и применимый порог

#### Scenario: Термины запроса вне словаря

- **GIVEN** обученная модель, запрос «Заметка по клиенту», где стем «заметк» отсутствует в словаре LSA
- **WHEN** выполняется поиск
- **THEN** ответ содержит подсказку, что часть терминов запроса вне словаря LSA, с отсылкой к секции точных совпадений

#### Scenario: Смешанный запрос подавлен гейтом покрытия

- **GIVEN** `lsa_min_query_coverage = 0.6` и запрос
  `"asdkjhasd zzzzz несуществующее"`, где распознано 1 слово из 3
  (покрытие 0.333)
- **WHEN** выполняется поиск со слоем `both`
- **THEN** секция семантически близких пуста, exact-секция не затронута
- **AND** метаданные содержат причину `query_coverage`, покрытие 0.333, порог
  покрытия 0.6 и нераспознанные слова `asdkjhasd`, `zzzzz`
- **AND** число отсеянных результатов не заполняется

#### Scenario: Полностью нераспознанный запрос

- **GIVEN** запрос `"asdkjhasd zzz"`, в котором нет ни одного распознанного
  слова (покрытие 0)
- **WHEN** выполняется поиск со слоем `both`
- **THEN** секция семантически близких пуста, метаданные содержат причину
  `query_coverage` и покрытие 0

#### Scenario: Покрытие ровно на пороге

- **GIVEN** `lsa_min_query_coverage = 0.6` и запрос с покрытием ровно 0.6
- **WHEN** выполняется семантический поиск
- **THEN** гейт не срабатывает (условие строгое `<`), применяются только
  фильтры cosine и относительного cutoff

#### Scenario: Порог покрытия отключён

- **GIVEN** `lsa_min_query_coverage = 0` и смешанный запрос с покрытием ниже 0.6
- **WHEN** выполняется семантический поиск
- **THEN** гейт покрытия не применяется, секция фильтруется только по cosine
  и относительному cutoff
