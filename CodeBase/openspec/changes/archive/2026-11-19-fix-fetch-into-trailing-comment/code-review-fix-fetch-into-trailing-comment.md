## Findings

### C1 (Minor) — `gofmt -l internal/review/` не пуст: CRLF в изменённых файлах

`gofmt -l` возвращает `review_parser.go` и `review_rules_test.go`; в них 3119 CRLF-пар (остальные файлы пакета — LF). Проверка содержимого с нормализованными переводами строк даёт gofmt-clean, и `git hash-object --path` (clean-фильтр) совпадает с LF-версией — значит в репозиторий уйдёт корректный LF-blob. Тем не менее task 3.1 («`gofmt -l internal/review/` пуст») в текущем рабочем дереве не выполняется, и любой локальный/CI-гейт по рабочему дереву упадёт.

Рекомендация: нормализовать переводы строк в двух файлах до коммита (или зафиксировать `.gitattributes`/`.editorconfig`), чтобы локальная проверка и задача 3.1 были честными.

### C2 (Nit) — устаревшие doc-комментарии про `LineEnd`

`parseAllFetchIntoStatements` (:441–442): «LineEnd — последняя строка, реально давшая переменную»; `fetchVariablesLineEnd` (:510–512): «реально содержащей одну из переменных». После Decision 2 спан может продлеваться чисто-комментарной строкой, где переменная только упомянута (это осознанное безопасное перерасширение). Комментарии стоит переписать: «последняя строка с вхождением переменной, включая упоминание в комментарии (skip-спан не сжимается)».

### C3 (Minor, edge) — незакрытый `/*` внутри FETCH больше не ограничивается границами

Если в операторе FETCH встретился `/*` без закрывающего `*/`, inBlock остаётся `true` до EOF, boundary/stop-проверки больше не срабатывают, сбор уходит до конца файла, а последующие FETCH-операторы пропускаются (`i = len(lines)-1`). До изменения следующая строка с `fetch`/`select`/`set` завершала оператор, поэтому поведение на битом/обрезанном SQL изменилось.

На синтаксически валидном SQL недостижимо; на реальных файлах FA не проявляется. Варианты: (а) задокументировать в Non-Goals как принятый риск, (б) добавить защитный предел на размер оператора (например, прекращать сбор при `inBlock` и отсутствии закрытия N строк), (в) тест на незакрытый блок.

### C4 (Nit) — дрейф номеров строк в артефактах

После вставки кода ссылки в design.md/tasks.md устарели: `parseFetchIntoStatement` теперь :245 (не :228), `fetchIntoStatementLine` :531 (не :497), `parseAllFetchIntoStatements` :443 (не :422), строки сбора :478–490 (не :448–458). На смысл не влияет; при архивации можно не править.
