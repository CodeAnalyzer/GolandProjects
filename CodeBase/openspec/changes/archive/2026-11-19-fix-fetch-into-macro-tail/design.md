# Design: fix-fetch-into-macro-tail

## Context

После fix-fetch-into-trailing-comment (архив 2026-11-19) разбор FETCH INTO считает переменные корректно при комментариях, но теряет последнюю переменную, когда за списком переменных следует standalone-вызов Diasoft-макроса, склеенный парсером в один фрагмент (см. proposal.md — Why). Механизм: `reParserFetchIntoBoundary` (review_parser.go:21) и `isFetchStatementStopLine` (:591) распознают начало нового оператора только по ключевым словам (`select/exec/set/...`) — макро-строка (`M_BUSINESSLOG_BLOCK_END('...')`) не матчится, попадает в CSV-часть `variablesPart`, и анкорный `reParserFetchIntoVar` (`^\s*@var\s*$`) отбрасывает последнюю переменную.

Потребители фильтров замкнуты на FETCH-пути (проверено grep): `reParserFetchIntoBoundary` → `findFetchIntoTailBoundary` → `parseFetchIntoStatement`; `isFetchStatementStopLine` → сбор продолжений в `parseAllFetchIntoStatements` (:487). `isCursorDeclarationBoundary` — отдельный предикат, в изменении не участвует.

Оба фильтра исторически расширяются синхронно (прецедент: B1 в fix-cursor-redeclare-positional-scope — стоп-слова `select/exec/...` добавлены сразу в оба).

## Goals / Non-Goals

**Goals:**

- Standalone-макровызов распознаётся как граница FETCH-оператора в обоих хвостовых фильтрах — на fragment-пути (`parseFetchIntoStatement`) и file-пути (`parseAllFetchIntoStatements`).
- `cursorFetchArguments` и `datatype` видят полный список переменных, включая последнюю перед макросом.
- `varUseAfterCursor` получает полные множества переменных FETCH; строки-аргументы макроса с переменными ниже DEALLOCATE перестают скрываться спаном FETCH и детектируются как использования (отражено дельтой требования).
- Многострочный standalone-макровызов (аргументы на следующих строках) распознаётся как граница по своей первой строке.

**Non-Goals:**

- Изменение `isCursorDeclarationBoundary`: макросы `M_ISOLAT`, `M_FORCEORDER`, `M_NOLOCK_INDEX(...)` — легитимные строки внутри SELECT декларации курсора; их нельзя делать границей сбора декларации.
- Standalone-макросы **без скобок** (`M_FORCEORDER`, `M_WITH_ROWLOCK`) после списка переменных: границей не признаются, дефект N−1 для них остаётся (в fa-contracts таких случаев после FETCH не найдено — принято осознанно, поведение зафиксировано unit-тестом `M_FORCEORDER` → false). Расширение паттерна без скобок требует отличения макроса от продолжения списка переменных и колонок — не оправдано на текущих данных.
- Открывающая скобка **на следующей строке** (`M_BUSINESSLOG_PARAM` / `  (@x, DSINT_KEY)`): границей не признается (`[ \t]*` не пересекает `\n` — следствие F7-решения о `\s*` → `[ \t]*`); в FETCH-контексте не встречается.
- Макровызов на той же строке, что и список переменных (`fetch c into @A, @B M_LOG_TABLE(x)`): на реальных файлах FA не встречается (проверено сканированием).
- Общий SQL-токенайзер макросов: паттерн вводится только в контексте двух FETCH-фильтров.
- Изменение batch-режима CLI `review --files` (агрегация `success` на списках с не-UTF8 путями — отдельная тема; приёмка обходит чистым списком).

## Decisions

1. **Standalone-макровызов = граница FETCH; паттерн `(?i)^m_[a-z0-9_]+[ \t]*\(`.**
   Diasoft-макросы конвенционально `M_XXX(...)`; сигнатура standalone-вызова: строка (после trim) начинается с `M_`-идентификатора и открывающей скобки. В `isFetchStatementStopLine` добавляется предикат `isStandaloneMacroCallLine` (компилированный регэксп `reParserStandaloneMacroCall`); в `reParserFetchIntoBoundary` добавляется альтернатива `\n[ \t]*m_[a-z0-9_]+[ \t]*\(`. Обязательный `_` исключает ложные срабатывания на функциях `max(`/`min(`/`mod(`/`month(` в начале строки. Вместо `\s*` используется `[ \t]*`: `\s` в Go-регэкспах включает `\n`, и паттерн мог бы матчить имя макроса и `(` на разных строках или несколько пустых строк между `\n` и именем в boundary-альтернативе.
2. **Синхронное расширение обоих фильтров; `isCursorDeclarationBoundary` не трогаем** (Non-Goals): M_ISOLAT/M_NOLOCK_INDEX — часть SELECT декларации; существующие тесты деклараций с макросами остаются зелёными как регрессионный фиксатор.
3. **Спаны FETCH сжимаются до реального оператора — осознанно; поведение `varUseAfterCursor` меняется и отражено дельтой.**
   Макро-строка перестаёт попадать в `statementLines` → `LineEnd` = последняя строка с переменной. Следствие: строка макроса с аргументом-переменной (`M_INSERT_ELDOC(@ContractCursID)`) ниже DEALLOCATE больше не скрыта skip-спаном и матчится как использование. Это устранение FN (передача переменной в макрос — реальное чтение); отличие от варианта A fix-fetch-into-trailing-comment: там спан не сжимался, потому что скрываемая строка была комментарием (не-использование по определению), здесь скрываемая строка — исполняемый код. Дельта требования «Использование переменной после закрытия курсора» фиксирует: standalone-макровызов — не строка-продолжение FETCH.
4. **Новый префиксный предикат вместо переиспользования `reStandaloneMacroLine` (review_helpers.go:2355).**
   В кодовой базе уже есть `reStandaloneMacroLine` (`(?i)^[\t ]*M_[A-Z0-9_]+[\t ]*\(.*\)[\t ]*\r?$`, потребитель — `stripStandaloneMacroLines` в `checkUsageVarInSameSelect`) и `reParserMacro`/`reDeletePtableMacro` — это разные по назначению определения, и новое — не дубль, а осознанный отдельный предикат: `reStandaloneMacroLine` требует закрывающую скобку на той же строке и матчит строку целиком, тогда как для границы FETCH нужен именно **префиксный** тест: (а) в `reParserFetchIntoBoundary` альтернатива обязана матчить префикс строки до произвольного хвоста; (б) многострочный вызов `M_X(@a,` / `...)` должен признаваться границей по первой строке — full-line регэксп его не видит. Паттерн оформляется одним компилированным регэкспом с комментарием-ссылкой на `reStandaloneMacroLine`; обе точки (`isFetchStatementStopLine` и boundary-альтернатива) выводятся из одного определения — разъезжаться паттерны не могут.
5. **Паттерн ограничен контекстом FETCH-фильтров.**
   Строки-кандидаты в зоне действия фильтров — продолжения списка переменных (`@`-префикс) и операторные ключевые слова; `m_...(` с них не начинается. Negative-кейсы (`max(`, `min(`, `month(`, `M_FORCEORDER` без скобок) фиксируются unit-тестами предиката.

## Risks / Trade-offs

- [Спаны сжимаются → использования переменных в аргументах макросов ниже DEALLOCATE станут находками `varUseAfterCursor` (сегодня FN)] → осознанно (Decision 3), отражено дельтой спецификации; unit-тесты обоих сценариев дельты; приёмка на эталонах допускает задокументированный diff с ручной верификацией новых находок как реальных.
- [Паттерн `m_[a-z0-9_]+\(` заденет функцию вида `m_foo(`] → в зоне фильтров строки-продолжения начинаются с `@`; функции с `m_`-префиксом в Diasoft-коде не встречаются; negative-кейсы `max(`/`min(`/`month(` в тестах.
- [Батч fa-contracts: 8 исходных находок] → фактически устранены 3 (`M_*`-хвосты); остаточные 5 — pre-existing FP двух других классов, отличных от `M_*`-хвоста и вынесенных в кандидаты-последователи: standalone-макросы без `M_`-префикса (`PROFILE_TIME_EX('...')` — `API_LN_AfterRuleA_MassCrtAcc.sql:118`, теряется `@RelType`) и UNION в SELECT декларации без FROM в первой ветке (selectPart захватывает `union select ...`, CSV даёт 3 «выражения» вместо 2 — `Cons_CalcAnnScheme8.sql:111/117/200/206`). Реальных рассинхронов среди остаточных — 0 (ручная верификация, tasks 3.3).
- [Регрессия: файлы с макро-хвостами меняют счётчики `varUseAfterCursor`/`datatype`] → эталонные прогоны 3.4 с фиксацией diff; InstrumentSO_LoadStates.sql — 11 находок либо задокументированный прирост с верификацией.
- [Batch-режим `review --files` на списках с не-UTF8 путями возвращает `success=false` с пустой агрегацией] → приёмка 3.3 готовит чистый список и проверяет `success=true`; сам дефект batch-режима — вне скоупа (Non-Goals).
