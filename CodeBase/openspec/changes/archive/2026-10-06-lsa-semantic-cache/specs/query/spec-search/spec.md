## ADDED Requirements

### Requirement: Кэш semantic-слоя (sidecar-файл + переиспользование в процессе)

Семантический слой spec-поиска SHALL использовать бинарный sidecar-кэш эмбеддингов
(`spec_lsa_embeddings.bin` рядом с остальными sidecar-файлами spec-LSA): заголовок
с поколением (generation), метаданные строк (включая имя продукта для фильтрации
по продукту в памяти) и эмбеддинги одним блоком float32 little-endian. Кэш
инвалидируется по поколению в заголовке (не по имени файла): промах или отсутствие
файла SHALL вызывать пересборку кэша из БД (`spec_embeddings`) с последующей
перезаписью; публикация файла MUST быть атомарной (временный файл + rename).
Повреждённый или устаревший кэш MUST NOT быть фатальным — semantic-слой
продолжает работу после пересборки из БД.

В рамках одного процесса модель (`spec_lsa_model.bin`) и эмбеддинги SHALL
загружаться один раз на поколение и переиспользоваться между вызовами: повторный
вызов semantic-поиска MUST NOT повторять декодирование модели и чтение кэша, а
ограничиваться дешёвой проверкой актуальности поколения в БД. При смене
поколения (переиндексация с переобучением модели) закэшированные модель и
эмбеддинги SHALL замещаться новыми. Доступ к кэшу MUST быть безопасен при
параллельных вызовах инструментов. Результаты поиска (состав выдачи, ранги,
диагностика OOV) SHALL оставаться идентичными поиску без кэша.

#### Scenario: Повторный вызов не перечитывает модель и кэш

- **GIVEN** обученная spec-LSA-модель и кэш эмбеддингов актуального поколения
- **WHEN** в одном процессе выполняются два последовательных semantic-поиска
- **THEN** оба возвращают идентичные результаты
- **AND** модель и файл кэша читаются с диска только при первом вызове

#### Scenario: Промах по поколению пересобирает кэш из БД

- **GIVEN** кэш `spec_lsa_embeddings.bin` с поколением, отличным от активного
- **WHEN** выполняется semantic-поиск
- **THEN** кэш пересобирается из `spec_embeddings` и перезаписывается атомарно
- **AND** поиск возвращает корректные результаты без ошибки

#### Scenario: Отсутствие кэша не ломает поиск

- **GIVEN** обученная модель, но файл кэша эмбеддингов отсутствует
- **WHEN** выполняется semantic-поиск
- **THEN** эмбеддинги читаются из БД, кэш создаётся, результаты корректны

#### Scenario: Смена поколения замещает кэш в памяти

- **GIVEN** в процессе закэшированы модель и эмбеддинги поколения G1
- **WHEN** индекс переобучен на поколение G2 и выполняется новый semantic-поиск
- **THEN** проверка поколения обнаруживает G2, модель и эмбеддинги загружаются заново
- **AND** выдача соответствует новой модели

#### Scenario: Фильтр по продукту применяется в памяти

- **GIVEN** кэш содержит эмбеддинги capability нескольких продуктов
- **WHEN** выполняется semantic-поиск с фильтром по одному продукту
- **THEN** в выдаче только capability этого продукта
- **AND** фильтрация выполняется по метаданным кэша без отдельного запроса к БД
