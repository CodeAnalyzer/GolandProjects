# План: справочник продуктов и `files.ds_product_id`

В этом плане добавляем таблицу-справочник продуктов, связываем с ней таблицу `files` через `ds_product_id` и при индексации автоматически определяем/создаём продукт по пути файла с нормализацией веток.

## 1) Схема БД
- Добавить таблицу `ds_products` (например: `id`, `product_name`, `created_at`, `updated_at`).
- Добавить уникальный индекс на каноническое имя продукта (`LOWER(product_name)` или `UNIQUE` по нормализованному значению).
- Добавить поле `ds_product_id BIGINT` в `files`.
- Добавить FK `files.ds_product_id -> ds_products.id` (без `NOT NULL`, чтобы не ломать нераспознанные пути).
- Добавить индекс `idx_files_ds_product_id`.

## 2) Модели и store-слой
- Расширить `model.File` полем `DsProductID`.
- Обновить чтение `files` в `internal/store/db_files.go` (`SELECT` + `rows.Scan`) с учётом `ds_product_id`.
- Добавить store-метод upsert/find для продукта по каноническому имени (например `GetOrCreateDSProductIDByName(name string) (int64, error)`).
- Учесть конкурентные вставки (через `INSERT ... ON CONFLICT ... RETURNING id` или эквивалентный двухшаговый безопасный паттерн).

## 3) Нормализация имени продукта из пути
- В индексере добавить функцию извлечения канонического имени продукта из `rel_path`/`path`.
- Правило: каноническое имя = `fa-` + два сегмента после `fa-`.
  - `fa-contracts-ext-develop/...` -> `fa-contracts-ext`
  - `fa-contracts-ext-factr-nomcost/...` -> `fa-contracts-ext`
  - `fa-cards/...` -> `fa-cards`
- Для путей, где `fa-...` не найден, возвращать пустое имя и сохранять `ds_product_id = NULL`.

## 4) Интеграция в `saveFile`
- Перед вставкой записи в `files` вычислять каноническое имя продукта.
- Если имя получено — получать `ds_product_id` через store `get-or-create`.
- Обновить `INSERT INTO files` в `internal/indexer/indexer.go`, добавив `ds_product_id` в список колонок/параметров.

## 5) Проверки и тесты
- Добавить unit-тесты на нормализацию путей (включая ветки `fa-...-develop`, `fa-...-factr-nomcost`, обычные `fa-cards`, и нерелевантные пути).
- Добавить тест(ы) store-метода `get-or-create` на идемпотентность и корректный возврат ID.
- Прогнать минимальные релевантные тесты по `internal/store` и `internal/indexer`.

## 6) Ограничения и запуск
- Миграция существующих данных не планируется (БД будет пересоздана через `codebase init`).
- Изменения должны быть обратимо локализованы: схема + store + индексер + тесты, без затрагивания доменной логики парсеров.

## 7) Обязательное требование: потокобезопасность справочника продуктов
- Индексация выполняется параллельно, поэтому реализация обязана корректно обрабатывать конкурентное добавление одного и того же продукта из нескольких потоков.
- В `ds_products` обязательно должна быть уникальность канонического имени продукта (через `UNIQUE`/уникальный индекс, при необходимости по нормализованному `LOWER(product_name)`).
- Получение `ds_product_id` должно выполняться атомарно через upsert-паттерн (`INSERT ... ON CONFLICT ... RETURNING id` или эквивалент), чтобы все потоки получали один и тот же `id` без дублей.
