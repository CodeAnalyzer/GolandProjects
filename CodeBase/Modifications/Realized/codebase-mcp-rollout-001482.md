# План внедрения MCP для CodeBase

Этот план переводит `CodeBase` на явный режим `codebase mcp` с поэтапной поставкой всех query-подкоманд через MCP-tools, сохраняя CLI-совместимость и контроль качества после каждой итерации.

## Зафиксированный контракт формата

- MCP: возвращает **чистые данные домена** (без CLI envelope).
- CLI: сохраняет текущий envelope (`success`, `format_version`, `command`, `meta`, `error`).
- Ошибки MCP: через стандарт MCP (`isError=true` + диагностическое сообщение), без CLI-обертки.

## Базовые архитектурные решения

- Выбран только явный запуск MCP: `codebase mcp`.
- `main.go` остается минимальным, режим задается подкомандой в `cmd`.
- В `mcp`-режиме отключается любой немашиночитаемый вывод в `stdout` (баннер/текст), `stdout` используется только транспортом JSON-RPC.
- MCP handlers используют внутренний сервисный слой/функции, а не вызов Cobra-команд.

## Итерации (с обязательным акцептом после каждой)

### Итерация 1 — Каркас MCP и безопасный запуск

**Цель:** добавить инфраструктуру MCP без функционала query.

- Добавить зависимость MCP SDK в `go.mod`.
- Создать пакет `internal/mcp/` (сервер, регистрация tools, базовые handlers, адаптер ошибок).
- Добавить подкоманду `codebase mcp` в `cmd`.
- Гарантировать отсутствие баннера и прочего text-output в `stdout` для `mcp`-режима.
- Добавить минимальный smoke tool (например `codebase.ping`) для проверки канала.

**Проверка итерации:**

- `go build ./...`
- `go test ./...`
- Ручная проверка старта `codebase mcp` и инициализации MCP (inspector/client).

**Гейт:** остановка и ожидание акцепта пользователя.

### Итерация 2 — Выделение сервисного слоя query (без изменения контракта CLI)

**Цель:** подготовить переиспользуемые внутренние функции для MCP.

- Вынести исполнение query в внутренний слой (`internal/...`), чтобы:
  - принимать типизированные аргументы,
  - возвращать чистые данные и ошибки,
  - не зависеть от Cobra/глобальных флагов вывода.
- Адаптировать CLI к использованию этого слоя, сохранив текущий JSON/text envelope 1:1.

**Проверка итерации:**

- `go build ./...`
- `go test ./...` (особенно `cmd/query_execution_test.go` и смежные).

**Гейт:** остановка и ожидание акцепта пользователя.
